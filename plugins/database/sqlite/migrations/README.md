# SQLite 插件数据库迁移

主库建表 SQL、嵌入资源和迁移加载器由 SQLite 数据库插件维护，随插件编译发布。插件在返回可用后端前完成建库和版本迁移，宿主不需要读取或执行外部建库脚本。发布工具从此目录读取插件声明的 Schema 历史，不使用宿主目录或旧路径兼容入口。

迁移文件整理遵循[工作约定](../../../../AGENTS.md)。当前加载器接受独立迁移和带分段标记的合并文件；文件前缀为最后一个版本号，每段以独占一行的 `-- migration: 原文件名.sql` 标记原始版本。

当前保留 036—039 四个独立版本，001—035 已合并为带原始分段的历史文件。历史版本 028 新增作品包副本类型索引，并将旧包及对应导入回执的类型补为 `directory`；从 027 升级仍会在执行前保留 `before-028` 备份。029 为扫描后的封面导入增加 `importArtwork` 原因，重建触发和动作表时完整保留既有记录、策略及外键；升级前保留 `before-029` 备份。030 新增按用户和录音隔离的默认来源偏好及成员移出后的清理触发器；升级前保留 `before-030` 备份。031 增加独立修订的录音封面偏好；失效候选保留人工偏好编号，但不阻止媒体垃圾回收，升级前保留 `before-031` 备份。032 为单次本地目录刷新增加 `refreshMetadata` 原因，重建触发和动作表时保留已有记录、策略、任务关联、动作及外键约束；升级前保留 `before-032` 备份。033 新增目录刷新任务的持久取消意图及资源释放确认时间，取消后阻断后续扫描发布与元数据应用；升级前保留 `before-033` 备份。旧包树、私有来源绑定、作品资料及其他幂等记录继续保留。

加载器校验版本连续、无重复、SQL 非空且文件前缀与末段版本一致。执行、事务、`schema_migrations` 记录及 `before-NNN` 升级备份逐版本进行，已有数据库可以从合并文件内的旧版本继续升级。备份和发布清单使用 Schema 版本，不使用 SQL 文件数量。更改合并策略时需同步核对加载器及旧库升级兼容性，不能只改文件名。

034 将旧分析器身份的指纹任务及索引原文移入 `retired_fingerprint_evidence` 审计表，撤销旧指纹发布、相关待确认候选和请求幂等记录，新请求重新提取。原歌曲、录音关系、授权、用户及其他任务不变；旧媒体由正常回收处理，备份引用仍受保护。迁移前保留 `before-034` 备份，不在运行代码加入旧 JSON 兼容分支。

035 将曲目歌手数组中的每个字符串按 `/` 拆分，去除 Unicode 首尾空白及空项，再按首次出现顺序精确去重。仅处理有效的字符串数组，曲目其他字段、来源与录音关系不变；已有固定查询快照保持原文。存在实际修改时递增曲库修订，迁移前保留 `before-035` 备份。

036 增加作品的普通曲目展示选项，默认关闭。持有抓轨副本的旧音乐作品转入 CD 专辑，作品、包和音轨的 ID 保留。ASMR 抓轨副本仍归 ASMR。升级前保留 `before-036` 备份。

037 新增歌手、专辑、曲目、来源及署名和曲序关系。迁移在首次导入时保留已有来源与录音 ID、默认来源、CD 专辑和可追溯的时间戳。

038 将普通歌单、收藏和音乐最近播放迁入共享条目表，保留旧歌单中明确选择的来源和原有播放时间。有作品归属的旧播放记录进入待交付队列，插件成功写入自己的历史后由宿主确认。

039 重建收藏归并触发器，使用显式主键冲突处理。多个已收藏来源归并为同一曲目时保留已有规范曲目的收藏时间和指定来源，再清理旧曲目条目；已应用 038 的数据库也会执行此修复。
