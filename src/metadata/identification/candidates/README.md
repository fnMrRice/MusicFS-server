# 本地待确认候选

本包是无数据库、文件访问或网络的纯比较模块。服务层先从可信存储取得调用者可见的当前资产，再提供完整文件已验证摘要及已发布指纹。`VerifiedHash` 仅表示 Server 实际读取完整容器得到的证据，不能由 Provider 申报值、PCM 摘要或 HTTP 请求直接构造。证据与当前 `AssetRef` 不一致时跳过，不让旧版本证明新资产。

`Compare` 只比较一对已授权输入；`Find` 接收一个锚点、最多 256 个来源，以及双向排除/人工归属冲突 pair，先移除被阻止的 pair，再比较。它不枚举全库，不删除或折叠来源。返回最多 20 个候选，按分数、来源 ID 确定性排序；同一 SourceTrack 不与自身比较，重复输入来源报错。

算法版本为 `local-candidates-v1`：

- 两端当前完整文件已验证 SHA-512 和实际字节长度均相同：100 分，保留两个来源及资产绑定；标签变化不削弱该字节证据。调用者缺少已知实际文件长度时，不构造 VerifiedHash。
- 指纹：两端 Detail 有效且质量均为 available，完整 Identity 相同，请求起点/时长相同，实际 PCM 覆盖比例至少 80%。搜索 ±24 个原始指纹项，要求至少 50 项且覆盖短者至少 80%；Hamming BER 不高于 0.08 才产生候选，基础分 70–90，再由标题/歌手/时长最多加 9 分。每次 Find 最多 1300 万次 popcount，取消可在各比较窗口间生效。
- 缺少支持候选的指纹时，标准化完整标题相等、非空歌手交集、双方已知且正数时长差不超过 2 秒，产生 35 分 metadataOnly 候选。只折叠 Unicode 空白和大小写，保留标点、括号及 live/remix 等版本词。兼容可比较的指纹已经超出 BER 门槛时，不再降级采用标签。

不同文件 SHA-512 不足以证明不同录音，例如重新编码或标签变化，因此不单独否定弱标签候选。short/lowInformation 指纹不参与比较；若存在独立标签依据，输出只能明确标为 metadataOnly。不同请求范围不猜测对齐，实际范围较短也不会被补零。

分数只是人工审核优先级，BER 只是本地保守筛选参数，不是概率、置信度或识别准确率。`OffsetItems` 是搜索索引，不能当作播放时间映射。所有结果均 `RequiresConfirmation=true`；本包不修改 Recording、来源权限、人工决策或歌单，不生成 TimelineEvidence。14 个已实测合成向量包含纯音碰撞与不同演绎的相似反例；仍需人工确认是否属于同一录音。
