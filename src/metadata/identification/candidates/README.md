# 录音匹配候选

本包向评分插件提供已授权的当前资产与证据，再校验返回结果。[Find](find.go) 接收一个锚点和最多 256 个来源，先过滤人工排除及归属冲突，最多返回 20 组候选。每组结果均需人工确认。录音关系由[匹配服务](../../matching/)维护。

## 标准评分

[标准评分插件](../../../../plugins/matching/standard/) 实现 `local-candidates-v1`。分数用于安排审核顺序。

| 依据 | 条件 | 分数 |
| --- | --- | --- |
| 文件完全相同 | 宿主读完两份当前文件，SHA-512 和实际字节长度均一致 | 100 |
| 指纹吻合 | 算法身份、请求范围一致，质量为 `available`，实际 PCM 覆盖率至少 80%。在 ±24 个原始指纹项内寻找对齐，至少比较 50 项且覆盖短者的 80%，比特错误率至多 0.08 | 基础 70–90，标题、歌手与时长最多再加 9 |
| 仅元数据 | 无可支持的指纹，完整标题规范化后相等，有共同歌手且正时长相差至多 2 秒 | 35 |

评分只使用绑定当前 `AssetRef` 的证据。来源自报摘要与 PCM 摘要不能构造 `VerifiedHash`。文件 SHA-512 不同仍可能是同一录音的不同编码；可比较的指纹已超过错误率门槛时，不再按相似标签产生候选。

标题和歌手比较仅折叠大小写与空白，保留标点和 live/remix 等版本词。每次搜索最多执行 1300 万次 popcount，`OffsetItems` 仅记录指纹搜索位置。播放定位需独立的时间轴证据。

[测试向量](../../../../tests/testdata/identification/README.md)中有两种频率的纯音产生了完全相同的指纹，这也是结果需要人工复核的原因。
