# 服务端音频处理

本文说明当前处理链；跨端播放语义以[总体架构](../../../docs/architecture.md)为准，精确接口见 [OpenAPI](../contracts/openapi.yaml)。通用音频图、其他输出格式和 C++ Worker 均不因本设计而视为已实现。

## 角色与当前路径

Provider 提供授权来源，Resolver 选择来源和输出，Audio Worker 处理音频，Stream Gateway 鉴权交付。Scraper 不传输音频，处理结果不写回音乐原件。

- 格式兼容且不需要处理时，PCM16 WAV、MP3 和原生 FLAC 使用原流或字节代理。客户端上报 `audio/flac` 为 `maybe` 或 `probably` 时可直接接收 FLAC；未声明支持、强制处理或需要声道转换/DSP 时进入处理链。
- NCM 先由独立解密插件提取内部编码字节；纯解密为 `proxy`，需转码或 DSP 时再进入处理链，见 [NCM](ncm.md)。
- 当前处理输出提供 MP3 单/双声道与 Opus/WebM 5.1、7.1 环绕声，目标码率按来源音频选择。默认禁用听感效果与声道插件，客户端模式也强制旁路，按来源选择输出声道；必要编码兼容降混由 FFmpeg 完成。仅显式启用且服务端执行时，独立声道插件转换到配置布局，再执行用户 gain、配置 DSP 和编码。参数、转换矩阵及布局约束见[常见 DSP 与声道转换](../plugins/dsp-effects.md)。
- `audio.normalize` 为指纹提供独立规范化路径，跳过播放 DSP 链。

## 插件与控制边界

内置音频控制面在主进程独立内存流上运行版本化 JSON-RPC，只有显式外部模式使用 stdio。正文仍走任务限定的二进制通道，不在 JSON 中传 PCM。Host 管理授权、超时、取消、背压和资源回收。实际字段见 [v1 Schema](../contracts/plugins/v1/protocol.schema.json)。

安装包的 `release.json` 记录官方音频 Worker 版本，Host 精确校验后发送请求；旧版本不支持当前按来源选择的完整编码身份，空链部署也须配套升级。节点参数仍为版本 1。内置 EQ、压缩器、混响支持有状态处理；外部 Worker 保持旧双声道无状态约束，详见 [DSP 插件](../plugins/dsp-plugins.md)。

外部 DSP v1 仅允许无状态、固定格式和帧数、保持时标、零延迟、无尾音节点，启动前验证程序摘要。当前节点均为必需节点，失败明确报错，不自动旁路。部署 DSP 配置重启生效；Web 的个人覆盖及管理员全局默认对下一次播放生效，活动会话固定旧链与缓冲区。内置节点支持输入输出布局协商和终止标记，实际处理块为 64–16384 帧，外部 v1 仍最多 4096 帧；见[DSP 配置](../plugins/dsp-settings.md)。普通音频插件停用仍在重启后生效，保存停用不会中断当前管线或拒绝新工作。实例配置重建按工作租约收尾。

Server 官方内置插件全部运行于主进程，FFmpeg/ffprobe 工具仍可按受控任务外部执行。内置代码共享地址空间，取消依靠协作，不具备插件崩溃或卡死隔离；显式外部插件使用原协议与进程回收机制。未来 C++ 内置桥接或外部入口须分别遵循 [CMake / C++23](../../../docs/native-plugins.md)并验证，当前没有已验证的 C++ DSP 实现，也不直接加载 Client DLL。

## 播放表示与处理身份

客户端提交实际 codec、container、MIME、传输和定位能力，Server 只选择已支持的输出。仅显式启用的非空配置链或服务端 5.1/7.1 布局强制 `processed`；按布局要求 MP3 或 Opus/WebM，缺少兼容路径返回明确错误，不静默降级布局。

仅在需要转码时，使用已绑定来源资产版本的 `bitrateBps` 选择最接近的目标码率。MP3 使用 32、40、48、56、64、80、96、112、128、160、192、224、256、320 kbit/s 标准档位，等距时选择较高档位；超出范围取端点。Opus 使用 500 至 `256000 × 输出声道数` bit/s 范围内最接近的整数目标值，与 [FFmpeg libopus 编码器约束](https://github.com/FFmpeg/FFmpeg/blob/n6.1/libavcodec/libopusenc.c)一致。未知或非正源码率回退到原有默认：MP3 128、5.1 Opus 256、7.1 Opus 384 kbit/s。NCM 使用扫描时解封后探测的内层音频码率，不用外层文件大小或临时 PCM 的码率替代。

MP3 立体声输出身份为 `mp3-<kbit/s>`，单声道为 `mp3-mono-<kbit/s>`；Opus 默认目标保留 `opus-5.1` / `opus-7.1`，其他目标为 `opus-<布局>-<bit/s>`。目标码率写入不可变会话视图，并由同一身份解析为实际编码参数、播放描述、缓存键和时间轴证据。Opus 的 `bitrateBps` 是 VBR 编码目标，不承诺每一帧或最终容器平均值都等于目标。每次新播放按该来源选择；seek、同源恢复及有证据的跨源恢复保留会话编码身份。此策略不修改用户或管理员默认设置。

`effectiveProcessing` 按实际顺序报告声道转换、用户 gain 和配置节点、版本、参数及 `execution: server`。处理链修订统一为 `dsp-v1:<SHA256>`，绑定音效和声道插件禁用标记、转换版本、实际输出布局、有序节点、参数、外部程序配置/摘要及音频 Worker 身份。处理缓存与恢复证据使用同一身份，桌面转场由 Client 执行。

每个 attempt 固定源资产、输出 profile、处理身份、起点和 `representationId`。来源、字节版本、参数、编码配置或起点变化都产生新表示和地址；不能沿用旧 Range 或拼接缓冲。来源授权和版本检查不会因缓存命中省略，见[处理缓存](processed-cache.md)。

`outputProfile` 描述服务端实际交付的编码流，不代表浏览器解码后或音响设备的输出格式。原流 WAV 从已有头部校验中回传声道、布局、采样率和码率；原生 FLAC 校验固定快照的 STREAMINFO、元数据边界和首帧标识，回传其中的声道、采样率与已知时长，不仅依赖扩展名或扫描标签。完整帧解码由客户端完成。原流 MP3/FLAC（包含 NCM 解密后的音频）复用固定播放快照的有界探测补充码率和布局等属性，多声道布局未知时省略。`bitrateBps` 单位为 bit/s，处理流使用输出 profile 的目标码率，原流使用实际音频探测结果，不继承 NCM 外层文件的码率。探测不可用或失败时仍允许结构有效的原流播放，省略未知属性，不默认双声道或猜测码率；这些展示属性不写入数据库。

## Range、定位与恢复

本地原流先建立受磁盘配额约束的私有固定快照，再交付真实单 Range。只有固定且可随机访问的表示声明 `byteRange`，不继承其他表示的长度或验证器。

处理输出边生成边交付，成功完整输出可缓存；命中仍为 `processed/timeRestart`，不提供处理流字节 Range。时间定位重新生成 attempt 和地址；有状态链从曲首重建后丢弃目标前帧，无状态链保留快速定位。客户端按 `positionOriginMs` 显示曲目进度并丢弃旧缓冲。未知时长或不能定位的输出不宣称可 seek。

`seek/recover` 校验当前 attempt、幂等键和代次，晚结果不能覆盖新状态。恢复次数与总时限有界。跨源继续播放须同时具备同 Recording、绑定两端资产及处理配置的有效时间映射、可定位输出；指纹相似或时长接近都不充分。当前人工固定偏移、恢复预算及 API 见[恢复与时间对齐](recovery.md)。

## 资源与失败

播放、后台指纹、解密和刮削分别限制准入；独立通道不代表 CPU、磁盘或网络的硬隔离。活动 attempt 持有输入和缓存引用，取消、断连、超时及退出回收无消费者任务。必要处理失败不得静默移除效果；无该依赖的原流仍可使用。

输入版本变化使未完成输出失效，不拼接新文件尾部。写回等待活动读取结束。持久发布按阶段恢复，半成品不能标完整；媒体对象、歌单与原件不随处理失败删除。

## 待扩展范围

- AAC/fMP4、通用重新封装与更多浏览器/桌面输出矩阵。
- 任意音频图、自定义声道矩阵、空间上混、任意重采样节点、变速、前视延迟、曲尾追加和状态检查点。
- 运行时热换图、Worker 内动态 C ABI、第三方插件权限隔离。
- 真实 NAS 和在线完整音频的资源接入与跨源续播。

这些扩展须分别补协议、实际音频与终端验收，不能从 FFmpeg 底层能力推定已经支持。
