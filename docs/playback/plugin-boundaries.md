# 音频插件与宿主边界

播放、后台媒体探测、指纹归一化和内容补全依赖 `audioruntime.Processor` / `Decoder`；计划、输出档案、媒体参数和处理身份使用 `sdk/audiotypes`。这些接口不导入 FFmpeg 或 NCM。官方实现集中在 `bootstrap/audio_bundled.go` 装配。

## 替换处理器与解封装器

可信装配先通过 `pluginconfig.Register` 声明插件身份、角色和 `AudioProcessing` 能力，再通过 `bootstrap.RegisterAudioFactory` 注册实际构造器。构造结果的插件 ID 必须匹配声明，启动、后台实例与管理重载复用同一构造器。FFmpeg 路径等选项属于官方适配器的部署配置，其他处理器无需提供这些工具。

当前部署只允许同时启用一个完整音频处理器和一个容器解码器。配置可保留其他禁用实现；同时启用同一角色的多个实例会明确拒绝，避免播放、后台任务和管理门禁绑定不同对象。通用解码链本身支持多层和多个候选解码器，独立嵌入者也可通过 `DecodeWith` 或播放配置的 `Decoders` 注入更多候选。

格式检测、扩展名和原生媒体检查器通过 `audiocodecs.Register` 注册；输出档案通过 `audioruntime.RegisterProfiles` 注册；可选设置通过 `codecsettings.Register` 注册。各实现负责校验自己的参数。HTTP 输出档案与时间轴只限定身份和字段形状，当前宿主再根据已注册档案及活动实例校验语义，不枚举官方编码器名称。

## 实际执行与租约

每轮解码按内容和优先级选择插件，`NeedsDecoding` 决定是否继续下一层。播放不再把“需要解封装”解释成 NCM；`effectiveProcessing` 来自实际插件输出的 `Processing` 声明。NCM 自行声明 `ncmDecrypt`，其他插件可声明自己的变换类型。

选中的有实例解码器统一获取租约，解码上下文、音频与附件读取均受取消约束；输出关闭后释放租约。播放额外保留会话租约，后台 `OpenNative` 使用相同准入规则。只有显式声明 `NativePassthrough` 的实现能在 native 请求中免实例透传，不能仅凭角色或输出格式推断这一能力。

## DSP 注册与处理缓存

`audio.RegisterDefinition` 同时注册目录声明和真实节点工厂。设置校验、参数目录、日志身份和管理状态读取该声明；增益、声道转换策略使用能力字段。`dspworker.RegisterBuiltin` 注册任意合规名称的内嵌协议实现；外部进程仍使用同一握手与数据协议。MFD1 v1 的双声道、无状态和 4096 帧限制属于协议约束。

处理缓存绑定插件 ID、插件版本、工作进程摘要、`DecoderSHA256`、管线修订、输入和输出档案。缓存文件使用中立 `.audio` 扩展名，不从 `mp3` / `opus` 档案前缀猜容器。缺少新身份字段的旧索引不会恢复，旧文件只参与清理；不双读旧身份字段。时间轴恢复使用当前处理器声明的档案和解码器摘要。

## 验证边界

集成测试用独立 PCM 处理器实际播放、复用缓存并恢复来源；用自定义解码器实际修改输出、声明任意处理类型并验证 HTTP 合同；用独立声道交换节点验证注册 DSP 的真实 PCM 输出。另有启动构造器、后台关闭与强制取消、跨插件缓存隔离、两个活动角色冲突测试。官方 FFmpeg/NCM 仍是默认交付实现，但替换实现不需要修改播放或后台业务分支。
