# 歌手、专辑、曲目和来源

曲目可以先建档再找音频。一首曲目的标题、歌手、流派和星级在切换默认来源后保持一致。来源记录负责把该曲目定位到特定插件实例的音频。播放器继续用已选中的来源 ID 建立会话。

| 表 | 保存内容 |
| --- | --- |
| `music_artists` | 歌手的内部 ID 和必填姓名。曲目的署名通过 `music_track_artists` 关联，可从曲目查歌手或从歌手查曲目 |
| `music_albums` | 稳定内部 ID、必填专辑名，可空的外部专辑 ID、封面文件地址、发行商与发行日期。外部专辑标记供 CD 专辑等插件使用。专辑与曲目通过 `music_album_tracks` 关联 |
| `music_album_release_identities` | 按账号保存音源确认的平台和发行编号。多个来源属于同一发行时共用一个专辑 ID，同名的不同发行分别建档 |
| `music_tracks` | 必填曲名，可空的封面文件地址、流派、年份和星级。每个账号独立管理其曲目，星级为 1 至 5 的整数，未评为 `null`。一首曲目可没有歌手、专辑或来源 |
| `music_sources` | 所属曲目、MusicFS 来源记录 ID、来源插件、实例 ID 和插件内来源 ID。同一个外部编号可以分别出现在不同账号或实例。通过 `sourceTrackId` 找到具体版本 |
| `music_playlist_entries` | 本人的歌单、绑定与条目 ID、顺序、曲目 ID 和可空的强制来源 ID。普通歌单、收藏与音乐最近播放共用 |

曲目和来源分别保存 UTC 添加时间与修改时间。API 通过 `createdAt`、`updatedAt` 返回系统维护的时间。发行日期、文件时间以及播放进度具有各自的含义。扫描记录保存原始观测，编解码、码率、文件大小、可用性及具体资产版本仍可按来源查询。读取逻辑曲目资料时以曲目表和它的歌手、专辑关系为准。

网易云和 QQ 音乐的在线曲目可提供原生发行编号。本地 NCM 或普通音频内嵌了网易云标签时，只有原始歌曲编号有效、曲名和完整专辑名相符、且至少一位署名艺人相同时，才采用其中的发行编号。首次导入的音源缺少编号时，在当前来源实例内按标签归类。同一实例已经有该名称的已确认发行时，新音源单独暂存。对已有音源，重扫优先保留人工指定的归属，再核对新观测与原曲目是否一致。

新来源先到、暂时独立建档后，原有专辑的成员也可能在重扫时补齐发行编号。若证据唯一指向原专辑，曲库将临时专辑的自动成员归回原专辑 ID。用户已编辑临时专辑或手工加入成员时，两张专辑各自保留。

手工重新选用同一份曲目表时，若旧专辑仍有无来源的占位曲目，可以用同一来源实例、同一原标签下暂存的音源补齐。原专辑没有已确认的原生发行编号，且曲位与音源的署名和时长能唯一对应时，才替换该占位。

## 查询和建档

- `POST /api/v1/library/tracks` 只需曲名即可创建。可传歌手名、已存在的专辑 ID、封面地址、流派、年份和星级。无来源时 `sources` 为空数组，`selectedSource` 为 `null`。
- `GET /api/v1/library/tracks` 浏览可见曲目。可用歌手 ID、专辑 ID 或实例过滤。`sourceOnly=true` 在分页前只保留绑定普通音乐来源的曲目；来源离线或暂不可播放仍算有来源。省略或传 `false` 保留无来源的资料曲目，游标绑定此条件。「曲目列表 → 全部曲目」使用此过滤；专辑、歌手分类内保留无来源曲目并以灰色展示。`GET /api/v1/library/tracks/{id}` 读取本人曲目；`PUT` 使用 `expectedRevision` 保存资料。
- `GET /api/v1/library/artists` 查询歌手。歌手可以在 `/library/artists/{id}/names` 保存多语言名称，曲目和歌手搜索均支持这些名称。
- `GET /api/v1/library/albums` 查询专辑。专辑可用 `POST` 建档，在 `/library/albums/{id}` 读取及修改显示名、发行商、发行日期和平台页面。只读的 `originalName` 保留首次名称。`sourceLinks` 保存多组 `{pluginId,url}`，每个平台对应一个 HTTPS 页面，空数组清除全部关联。可单独编辑链接，手动刷新时选择具体平台并对比资料。
- 专辑列表、详情及曲目内的专辑引用共用封面读取策略：已选刮削封面优先，其次详情图像、专辑原图、普通音乐成员图像和当前来源封面。按账号批量查询，隐藏作品的来源不参与回退；无可用图片返回 `null`，不从文件系统路径生成网页地址。
- 曲目行的 `albums` 折叠来自不同音源的同名标签，名称比较统一 Unicode 组合形式、大小写和空白，保留版本后缀。已有手工关联、人工编辑或刮削资料的专辑优先展示，同名的独立专辑各自保留。在某张专辑内保留该专辑链接，来源筛选或文件夹内优先展示本来源的标签。逻辑曲目返回的 `albumIds` 包含当前查询可见的全部成员关系，可用于核对专辑归属。
- 专辑刮削取得完整曲目后，在同一事务补齐无来源资料与专辑曲序；已有来源和人工资料保留，同发行版重刮按稳定位置引用复用曲目。按 `albumId` 查询时使用专辑关系位置及曲目 ID 排序，游标仍绑定账号、过滤条件与修订。没有音源的条目在专辑和歌手中灰色显示，「全部曲目」不显示这些条目。[完整专辑刮削](../metadata/online-scrapers.md)
- 已关联页面的专辑可主动刷新预览，再通过 `PUT /library/albums/{id}/metadata-merge` 按字段确认合并。名称、发行商和完整发行日期写主资料；歌手、风格、说明及原始日期精度保存在专辑详情。年份或年月不会补造月日。未勾选的字段、封面和曲序保持，勾选曲目表时才补齐实际条目；专辑原名与用户关联页面始终保留。
- 手工建档后可通过现有录音关联操作指定真实来源。手动指定的默认来源优先，自动选择仍按可用性、码率、文件大小及稳定身份排序。[来源配置与默认策略](recording-groups.md)

## 歌单与播放记录

每个本地歌单条目可以跟随曲目的当前默认来源，也可以指定自己的版本。同一首曲目在不同条目中可以有不同的选择。空来源曲目可以加入歌单或收藏。强制版本失效或脱离曲目时，该条目暂停播放，用户可以重新选择来源。旧歌单里已明确指定的来源迁移为强制来源。

收藏与音乐最近播放是账号的特殊歌单。浏览器确认音频开始播放后，上报实际来源、会话和尝试。Server 校验归属并为该次播放保存回执。CD 专辑、ASMR、电台在内容类型声明中启用 `library.separateHistory`，所以各有独立标签。CD 专辑曲目即使已勾选普通列表展示，播放记录仍归入 CD 专辑。

内容插件通过 SDK 的 `History` 接口记录和读取本类型的历史；宿主提供每个插件独立的私有状态空间。当前 CD 和 ASMR 按作品保留最近播放的音轨，电台按节目中的单集保留。三个插件各为每个账号最多保留最近 100 项。读取端点为 `GET /api/v1/me/content-history/{type}`。[HTTP Schema](../contracts/http.schema.json) · [OpenAPI](../contracts/openapi.yaml)
