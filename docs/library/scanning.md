# 扫描范围、排除规则与文件通知

Local Files 提供配置说明与校验 Schema，当前声明为 `local-import-v5`。宿主依次合成插件默认、实例默认、各目录默认和本次请求覆盖。管理员通过“添加本地目录”选择授权根或子目录，逐目录编辑查找设置；保存入数据库并重建实例，不自动扫描。YAML 限定访问权限，修改权限需重启；扫描请求只选择已配置音乐根 ID。具体接口见[插件配置](../plugins/plugin-configuration.md)。

```yaml
importDefaults:
  recursive: true
  maxDepth: 0
  skipHidden: true
  respectNoMedia: true
  importLyrics: false
  excludePatterns: ['**/cache', '**/*.tmp']
```

示例为实例默认值；`config.musicRoots[].importDefaults` 可覆盖单目录，省略时继承。旧 YAML 仅在数据库尚无设置时提供初始值，之后以管理 API 保存的数据库配置为准。默认递归不限深度、无排除，根本层文件深度为0；关闭递归只扫描当前目录。开启递归时0表示全部子目录，1—64限制进入层数。每实例最多256个音乐根，单次扫描上限50,000首。

Host 遍历、目录通知注册和数据库缺失对账共用范围判断。不限深度仍受授权、排除、取消及资源上限限制；超过通知目录预算退为周期复核。

## 隐藏内容与 .nomedia

高级选项默认跳过隐藏内容并遵循 `.nomedia`。`skipHidden:true` 同时过滤点开头文件、目录和 Windows 隐藏属性条目；`respectNoMedia:true` 检查标记是否存在，不读取其内容，并跳过所在目录及子树。两项可独立关闭。允许访问的路径仍由部署授权决定，目录选择树不因导入筛选缩小授权展示。宿主为本轮扫描记录实际跳过的路径，发布时保留这些范围中的旧曲目，不能将未扫描内容当作丢失。

显式选择的隐藏目录仍作为音乐根扫描，隐藏筛选只作用于根内条目。`.nomedia` 从每个所选根开始检查：根本身包含标记时跳过整个根，不向根外的祖先目录查找标记。监听保留标记所在目录的通知，以便移除标记后重新扫描该目录。

新实例的有效默认值包含两个 `true`。旧持久化扫描计划省略高级字段时保留原先 `false/false` 的含义和摘要；当前配置声明为 `local-import-v5`，旧声明的任务不能悄然套用新默认范围。

## 规则语义

每条规则相对所选的每一个音乐根，用 `/` 分隔、所有系统均大小写敏感。最多32条，每条UTF-8最多256字节，合计最多8KiB；规则先排序，重复拒绝。字符类、花括号、否定、绝对路径、盘符、反斜线、控制字符以及空/`.`/`..`段不接受。

| 规则 | 作用 |
| --- | --- |
| `private` | 排除根下名为private的条目；若为目录，排除整支 |
| `**/cache` | 排除任意层名为cache的条目及目录后代 |
| `*.tmp` | 仅根本层匹配扩展名tmp的条目 |
| `**/*.tmp` | 任意层匹配扩展名tmp的条目 |
| `disc/?音.wav` | disc下一层，`?`为一个Unicode字符 |
| `**` | 排除整个选中范围；不从旧库删除已存在曲目 |

`*` 和 `?` 不跨 `/`；只有独立段 `**` 可匹配零或多层。匹配目录将停止进入它，未触达的分支不能声称完成观察。规则没有“后面的包含覆盖前面的排除”顺序含义。

## 请求与既有曲目

先读 `GET /api/v1/provider-instances` 获取当前 `configuration.schemaRevision` 和 `roots`，再提交完整模式/修订/根ID及部分选项：

```json
{"mode":"full","schemaRevision":"local-import-v5","rootIds":["local"],"options":{"excludePatterns":["**/cache"]}}
```

每一层的 `excludePatterns` 都整组替换，省略继承、显式 `[]` 清除，不自动追加。`scripts/scan.ps1 -ProviderID b1548e96-3081-5c9c-8376-bf290e369d51 -ExcludePatterns '**/cache','**/*.tmp'` 可提交本次规则；传 `-ExcludePatterns @()` 清除实例继承。登录、Origin/CSRF、幂等键和等待任务由脚本处理。

有效递归、规则、根身份、插件/配置/声明版本共同进入不可变计划及摘要；有独立目录设置时使用 `rootOptions` 按根记录完整有效值。任务响应的 `effectiveRootOptions` 提供相应目录选项，未列出的目录使用 `effectiveOptions`。同一规则集或根列表调换顺序可重放相同幂等键，改变有效规则则冲突。Host遍历、返回观测检查和数据库缺失对账使用同一个匹配器；被排除、超深或未选择根的旧记录保持原样，包括已验证摘要和人工内容。清除排除后，完整复核才可以把确实消失的同一来源标为missing。排除不是撤销读取权限，也不是删除曲库操作。

旧身份从被排除、未选根或超深位置移入本轮允许范围时，宿主也会拒绝重绑，以保护本轮范围外的旧记录。此时请显式选择同时覆盖旧、新位置的完整范围，必要时清除排除规则或提高深度，再复核；合法移动并非永久无法扫描。拒绝的整次发布不会部分改动曲库。

扫描失败/取消/根身份改变保留旧库；增量模式仍执行受控完整复核，不能从文件名或扩展名推断可解码。分页空闲5分钟内可续期，总寿命1小时，不允许无限续租。`retry_wait` 等待有界自动重试；`paused` 需修正原因后显式重提，不能用自动请求绕过暂停。

任务的 `progress.observed` 是本轮已接收并验证的来源数量。每页（最多200首）在读取音频元数据前持久化一次，运行中轮询任务即可看到进度；该计数不代表已发布到曲库。首次目录快照尚未完成时仍可能为0。每轮执行内数量只增不减，失败保留已发现数量；重试领取新代次时从0开始，过期代次和失效执行租约不能更新进度。

进入页面或刷新后可直接查询 `GET /api/v1/provider-instances/{id}/scan-status`，响应为 `{"job": ScanJob或null}`，无需重新提交扫描。查询仅包含当前用户、指定来源的已有任务，优先 `running`，其次 `retry_wait`、`queued`；同状态活动任务按创建时间、编号升序稳定选择。没有活动任务时返回最近更新的终态任务，无历史返回 `null`。来源离线仍可读取历史，未知或他人来源返回 `NOT_FOUND`；查询不会创建任务、领取执行权或改变进度。

目录统计通过 `GET /api/v1/provider-instances/{id}/root-statistics` 读取，返回 `{roots:[{rootId,trackCount,sizeBytes}]}`。统计来自当前用户、当前来源已完整发布的曲库，按根汇总仍为 `available` 的来源文件数量和原始文件大小；NCM 等封装文件按原文件容量计算，不按录音去重，不包含 `missing` 文件、歌词或封面附件。扫描进行中或失败时沿用上次发布结果，来源离线仍可查询，不遍历磁盘。配置中的空目录返回零值；无配置目录且无历史时返回空数组。

## 任务重试

手动目录元数据刷新使用同一创建接口和单目录计划，通过[任务队列](tasks.md)聚合扫描与后续元数据处理。全部刷新由客户端逐目录提交独立任务，分别查询与取消；扫描阶段成功不等于整个刷新任务完成。

每个逻辑扫描任务最多执行三次。`attemptCount` 计已领取次数，`retryCount` 计额外执行次数；`retry_wait` 仍是活动任务，同计划请求合并，不能补充次数或改变等待期限。

只有宿主明确标记可重试的 `TEMPORARY_FAILURE`、`RATE_LIMITED` 自动重试。基础退避为 1、2 秒，增加 0–25% 抖动；上游有效等待要求作为下限，总等待不超过 5 分钟。非法等待值会暂停任务。普通存储错误、资源变化和不完整协议不会仅因展示为临时错误而自动重试。

`AUTH_REQUIRED`、`ACCESS_DENIED`、`SOURCE_OFFLINE`、`PLUGIN_DISABLED` 进入 `paused`。处理原因后显式创建新操作；同一幂等键仍返回原暂停结果，扫描脚本不会自动绕过。重启时未完成执行计入已用次数，已有重试截止时间保持，预算不会重置。

等待不占 Provider 执行租约，到期重新获取代次；旧执行不能发布结果，失败保留旧曲库。任务结果连续持久化失败会停止后续扫描调度，修复存储后重启恢复。此策略只适用于扫描，不套用到指纹、补全、远程同步或写回任务。

## 文件通知与周期补漏

通知调度由宿主实施，仅 Local Files 支持，默认关闭。通过实例配置 API 保存 `watch` 后重建监听器；旧 YAML 仅用作首次配置初始值。插件与实例的当前运行开关也必须启用：

```yaml
config:
  watch:
    enabled: true
    debounceMs: 1000
    maxDelayMs: 10000
    fullRescanSeconds: 3600
  musicRoots:
    - id: local
      name: 本地音乐
      path: /music
```

`watch` 可省略，或只覆盖部分字段。`debounceMs`为100—30000毫秒；`maxDelayMs`为100—60000毫秒且不能小于去抖时间；`fullRescanSeconds`为30—86400秒。省略分别采用1000、10000、3600，显式0或null拒绝。时间是触发条件，执行仍须等待扫描队列与来源读取租约，不是完成时限。

启用后先完整复核。Windows使用目录通知，Linux使用inotify；变化合并为一次增量提示，持续事件达到最大等待时间也会提交。通知不直接更新数据库：任务仍固定当前实例已添加且获得授权的音乐根、每个目录有效的递归/深度/排除/歌词选项，并走正式扫描、代次和完整发布。单次手工扫描覆盖只影响该次任务，不修改监听默认范围。

每实例最多256个监听目录；每个授权根的目录注册遍历最多50,000个条目，采用每批128项读取。最多8个实际启用监听的实例。只对授权、深度内且未排除的目录分别注册非递归监听，不跟随符号链接扩展授权。每实例仅保留一个合并事件信号和一个待扫描标记；扫描运行或处于 `retry_wait` 时不会因事件洪峰新建大量任务。Windows每目录缓冲8KiB，最多2MiB/实例；Linux单实例读取缓冲32KiB。目录句柄、事件缓冲和后台循环在关闭时回收。

目录数量超限、目录不可读、平台/文件系统不支持或通知失败时，日志出现 `scan watch degraded to periodic reconciliation`，仍按周期完整复核；定期重试注册。通知队列溢出也触发复核。创建目录后会重建监听集合；注册与扫描之间仍可能有竞争，周期复核补齐丢失事件。网络文件系统的通知可靠性不作保证，尚未通过实际NAS验收。

权限、认证或来源离线使扫描进入 `paused` 时，本实例监听停止自动提交，日志为 `scan watch paused until restart`。修正依赖/权限后可手工扫描；恢复持续监听需要重启服务，不能靠新自动幂等键绕过暂停。日志只包含实例、任务和稳定错误码，不输出音乐根私有路径。
