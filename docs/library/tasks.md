# 目录刷新任务队列

任务队列当前接入本地目录元数据刷新，覆盖文件发现、基础标签读取以及歌词、封面处理。一个任务只刷新一个已配置目录；全部刷新由客户端按当前目录列表分别提交，不是一个包含全部目录的大任务。各目录可独立查看、排队和取消，某个目录失败不阻止其他目录执行。

## 创建与展示

客户端先读取 `GET /api/v1/provider-instances`，固定本次选择的目录和最新 `schemaRevision`。每个目录使用独立的 `Idempotency-Key` 调用现有创建接口：

```http
POST /api/v1/provider-instances/{id}/scan-jobs
Content-Type: application/json
Idempotency-Key: <本目录本次操作的独立键>
X-CSRF-Token: <当前会话令牌>

{"mode":"full","schemaRevision":"local-import-v5","rootIds":["local"],"options":{"refreshMetadata":true}}
```

该指令不修改目录导入设置。创建返回的 `jobId` 同时是任务队列中的 `id`；已存在的相同活动计划可复用该任务。响应不确定时，使用原请求和原键确认结果；全部刷新部分提交失败时，仅重试未确认的目录，不能重新创建已经成功提交或已取消的目录任务。等待中的任务不妨碍添加其他目录任务。

Web 在右上角服务状态右侧提供任务入口，徽标表示当前查询范围内的活动任务总数。默认查看“我的任务”；管理员可切换“所有任务”，查看任务所属账号并中断其任务。目录行编辑按钮右侧和本地音乐标题行的操作均命名为“刷新”，前者刷新该目录，后者按目录加入全部刷新任务。

## 查询与权限

客户端在 WebSocket 就绪后订阅本人的队列，直接使用首个 `tasks.snapshot` 展示列表和徽标。任务变化时，服务端推送首屏、当前范围的活动总数和已变更的历史记录。点击加载更多时用游标读取历史页。管理员切换范围或客户端重连时重新订阅，收到重置快照后补读之前已展开的历史页。详见[任务队列订阅](../contracts/control-channel.md#任务队列订阅)。

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/tasks?scope=mine&limit=50&cursor=…` | 按创建时间倒序、相同时间按任务编号倒序分页 |
| `GET /api/v1/tasks/{id}?scope=mine` | 读取一个任务及扫描、元数据处理汇总 |
| `POST /api/v1/tasks/{id}/cancel?scope=mine`，请求体 `{}` | 自然幂等取消或中断，要求当前会话与 CSRF |

WebSocket 订阅要求显式传入 `scope`，HTTP 查询省略该参数时使用 `mine`。管理员选择 `all` 后才接收或读取所有用户的任务。普通用户使用 `all` 返回 `ACCESS_DENIED`，本人范围内查询或取消他人任务返回 `NOT_FOUND`。HTTP 分页大小默认 50、最大 200；沿用当前范围返回的不透明 `nextCursor`，无后页时为 `null`。非法、重复或未知查询参数拒绝。

列表只包含显式 `refreshMetadata=true` 的目录任务。服务端在客户端离线期间继续执行任务。任务返回来源与目录显示名及不透明身份，配置已移除时名称回退为身份。当前 `ownerName` 使用账号标识。

## 进度与结果

| 状态 | 含义 |
| --- | --- |
| `queued` | 等待扫描或等待有界重试 |
| `running` | 正在扫描，或扫描完成后仍在处理元数据 |
| `cancelling` | 已记录中断请求，等待实际执行退出 |
| `succeeded` | 扫描成功且元数据处理全部结束，没有失败操作 |
| `failed` | 扫描失败或暂停，或元数据处理中出现失败 |
| `cancelled` | 已取消，后续不会继续发布该任务结果 |

`phase` 区分 `queued`、`scanning`、`metadata`、`finished`；客户端以 `status` 判断任务是否结束。`progress.observed` 为本轮已校验来源数，不等于已入库数；元数据进度以 `metadataCompleted / metadataTotal` 表示处理项数量。`result` 分别汇总更新、保留、未找到、失败的操作数，一个来源可有多个操作，不能把这些数字直接解释为歌曲数量。

扫描成功并不代表刷新完成，必须等待该扫描产生的全部元数据处理项结束。`activeCount` 包含当前范围所有页面的 `queued`、`running`、`cancelling` 任务，也包括仍在处理元数据的任务。

## 取消与恢复

等待中的任务可直接取消；正在执行的任务先持久化取消意图，再通知扫描与元数据执行上下文退出。界面分别使用“取消”和“中断”，请求发出后保持“正在中断”，直至服务端报告终态。内置插件使用协作取消，不强杀宿主线程。

取消事务撤销扫描和后续元数据发布资格，发布事务复核取消状态，防止迟到的扫描结果或刮削候选继续覆盖内容。已经发布的曲库或媒体引用保留，人工锁定内容仍遵循[元数据规则](../metadata/metadata.md)。取消不删除音频原件，也不回滚已经成功处理的项目。

取消请求与客户端连接解耦；请求断开不会撤回取消意图。重启恢复会结束遗留取消状态，不复活已取消任务。重复取消终态任务返回原终态与完成时间，不创建新任务。详细模型与端点见 [HTTP Schema](../contracts/http.schema.json) 和 [OpenAPI](../contracts/openapi.yaml)。
