# 重复识别与人工确认

标准匹配插件通过设置页面提供自动识别开关、最低分数输入框和“立即识别”按钮。默认自动识别，最低分数为 35；标签相符但没有音频证据的候选也可以出现，必须由用户确认。分数是排序依据，不是重复概率。

Server 周期检查每个用户当前可用曲目的资产、标签、文件哈希、音频指纹绑定和人工关联修订。变化后使用插件选择的候选桶执行全库识别。一次识别覆盖全部来源，按最多 20 个比较项分批发布；这与旧单来源比较 API 的 256 来源上限及 20 条结果上限不同，不截断到曲库前 256 条。不同批次只替换明确比较的来源对，既往批次不会被后续批次覆盖。

`GET /api/v1/matching/candidates` 按分数、候选 ID 分页，返回本人当前候选及双方曲目。曲目信息附已有录音的完整成员，避免确认候选时把单一来源从原关联组中拉出。过期资产、失效证据、已排除的对和两端已有人工分配的对不会作为当前候选返回。

自动任务只产生候选，不改写录音关联、文件、播放顺序或时间轴证据。候选合并继续使用 `POST /matching/links`，取消候选使用 `/matching/exclusions`，解除来源使用 `/matching/unlinks`。所有人工修改保持全局本人 `expectedRevision`、幂等键及审计保护。

任务进度、设置和动作幂等记录保存在数据库。页面关闭或离开不停止识别；Server 重启后重新检查未完成任务，重跑已处理的分批操作是安全的。同一动作键在后续任务完成后仍重放原结果；正在运行时不同键的新动作返回 `RATE_LIMITED`。设置更改在下一次识别时生效：开启自动时由后台检查触发，关闭自动时需点击“立即识别”。关闭自动检查不会删除已有候选或人工关联。

后台检查间隔为 10 秒。识别期间目录扫描、标签或人工决定变化导致快照冲突时，开启自动识别会在下一次检查重试；关闭自动识别时由用户重新触发，均不回滚人工操作。当前只读取已经生成的摘要和指纹，不会为识别任务自动启用音频指纹提取或完整文件哈希计算。
