# 完整离线备份与恢复

命令使用与数据相同版本的 `musicfs`。当前只恢复同操作系统、同架构、同数据库结构版本的备份；不会在备份时迁移数据库，也不会用旧程序尝试降级新库。媒体层的文件发布与回收说明见[媒体恢复](media-storage.md)。

存储插件增量：创建备份通过配置后端的维护接口生成便携 SQLite 快照，清单记录后端名称；旧清单默认 SQLite。验证不执行任何备份内程序；恢复统一落到内置 SQLite，并清空 DSP 链和外部 DSP 程序配置。存储及 DSP 程序只记录摘要，不随数据备份执行或恢复启动，见[存储插件](storage-plugins.md)。

## 创建与校验

先正常停止 Server。备份命令持有同一个 `server.lock`；仍在运行时明确拒绝，不复制变化中的插件状态。目标父目录须事先创建，且与 data/media/cache、音乐根互不包含。

```text
musicfs backup --config /path/server.yaml --output /path/backups
musicfs verify-backup --input /path/backups/<backupId>
```

Windows 同样支持这些子命令，路径使用实际本机路径并给含空格路径加引号。备份读取配置及现有文件，无需管理员登录令牌；`MUSICFS_DATA_ROOT` 等已有环境覆盖仍生效，应与实际启动环境一致。输出为英文 JSON，包含新建备份目录、版本和缺失媒体数量。

完整包包括：

- 一致性 SQLite 快照，以及快照实际引用的歌词、封面、指纹、缩略图和刮削文档；历史对象和人工选择也在其中。
- 原 YAML 文档和解析后的实际配置，后者包含当时路径/环境覆盖，但均不写管理员环境令牌。
- `providers`、`online` 和 `writeback` 的持久文件状态，包括本地稳定文件映射与原件写回恢复记录。
- 数据库结构版本、平台、Go/模块版本、配置的插件和外部工具可读取文件的 SHA-256。没有执行这些工具来推测版本；未取得的版本明确为 `unreported`。

`bundle.json` 是完整安装备份的完成清单；仅有媒体层 `manifest.json` 不足以恢复。校验同时检查文件摘要、完整数据库引用集合、数据库完整性及外键，拒绝截断/遗漏/重复引用、异常路径或链接。配置在复制期间发生手工修改也会失败；失败目录保留，重试生成新的编号。

媒体文件原先丢失或损坏时，备份会明确记录 `missingMedia`，不会假造文件。恢复后相应内容标为不可用，但索引、人工选择和历史仍保留。损坏的已复制备份文件则使整包校验失败。

当前上限为数据库 64 GiB、媒体对象 100,000 个（各最多 16 MiB）、插件/恢复状态 100,000 个文件、单状态文件 1 GiB、状态总量 8 GiB。达到限制明确拒绝；大库应预估目标磁盘容量。缓存、原音乐、原件旁边的写回备份/临时文件、TLS 私钥、管理员令牌和 Web/插件程序不包含在安装备份中。

## 恢复到新目录

```text
musicfs restore --input /path/backups/<backupId> --destination /path/new-installation
```

目标目录必须不存在，其父目录必须存在。不会覆盖原安装，也不接受备份目录内部的目标。先完整校验，再复制、再次校验和整理数据库；恢复失败保留 `.restore-incomplete`，Server 拒绝启动该数据目录。重新恢复到另一个新目录，不把部分恢复当完成。

成功后使用输出中的 `configuration` 路径。恢复配置将 data/media/cache 指向新目录，仅监听 `127.0.0.1:8080`，禁用全部插件、自动摘要/指纹/补全和原件写回，清除旧 Web/TLS 路径。旧会话被撤销，处理缓存索引清空，未完成配置写入意图被标为已替代。原配置保留在 `configuration.original.yaml` 和 `configuration.source.yaml`，供逐项复核。

使用 `musicfs token` 创建新的管理员令牌，通过 `MUSICFS_ADMIN_TOKEN` 提供；私钥和平台授权须从单独受保护的来源恢复。当前在线插件只实现匿名资料，没有可恢复的用户平台登录。确认插件制品摘要、FFmpeg/ffprobe/fpcalc、音乐根路径与原配置一致后，再显式启用需要的实例。先检查历史歌词/封面，再扫描和播放。

如果存在未完成原件写回，须同时保留原音乐卷及其恢复文件，按[写回恢复说明](writeback.md)处理；仅凭安装备份无法重建原音乐或继续写入另一份同名文件。恢复默认关闭写回，不会自动尝试修改原音乐。

## 升级与回滚

升级前用旧制品停止并创建、校验完整备份，保留对应版本的 Server、插件、Web 和外部工具清单。新版本在新安装目录中验证后再切换启动路径。回滚使用对应旧制品及旧备份恢复到另一新目录；数据库迁移不提供任意逆向降级，写回过的音乐也不会随数据库回滚自动还原。

备份含私人曲库资料、配置路径和操作历史，应放在受访问控制的存储中。管理员令牌和 TLS 私钥独立保存，不能只保存备份而遗失实际所需的凭据。当前流程没有声称远端对象存储、跨操作系统搬迁或断电耐久性在所有文件系统均已验证。
