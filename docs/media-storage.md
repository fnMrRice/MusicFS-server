# 媒体发布、回收与备份

歌词、封面、缩略图、完整刮削记录和指纹明细存放在独立 `mediaRoot`，与音乐原件和可重建播放缓存分开。上传和人工选用接口见[媒体说明](media.md)，两类派生文件见[派生媒体](derived-media.md)。下面的备份组件属于 Server 内部服务；完整配置/插件清单、管理命令和部署恢复入口在 P8 交付。

## 发布与重启

文件写入前创建持久意图，按 `prepared → written → published → referenced → finished` 推进。staging 文件验证格式、长度与摘要并落盘后，才发布不可变对象，再提交数据库引用。人工选用另以预期修订事务提交，上传预览不会自动替换已选内容。

启动恢复先于后台工作：未建立引用的任务转为 `aborted`，移除其 staging；已发布未引用的孤儿保留到回收宽限期。已引用内容校验通过后完成日志，丢失或损坏则标不可用。同名文件不能证明写入成功。已选内容后续损坏时保留人工锁和历史，读取返回明确错误。

## 保守回收

启动恢复后回收一次，之后每小时一批，每批最多 128 项；默认宽限期 24 小时，内部配置不得低于一小时。只处理日志确认已放弃的对象编号，不枚举未知路径。删除前在事务内重查引用，再删除该编号的 staging/objects 文件并记录回执。中断后可重复执行；一个损坏项不会阻止同批其他项。

任何内容对象、指纹索引、活动发布或备份清单都保护文件；历史、未选预览、失效引用同样受保护。人工文件没有缓存淘汰策略。未知文件、目录和符号链接不由回收器删除；日志只报告脱敏错误码，异常项保留等待修复。

## 一致性备份组件

`mediastore.Backups.Create` 要求提供已存在的绝对父目录，在其中新建随机编号目录。失败后用新编号重做，保留旧目录证据，不覆盖已有路径。

先写持久意图，再以 SQLite `VACUUM INTO` 生成快照。引用清单从只读快照读取，检查 schema、完整性和外键；不能从更晚的在线库取清单。所有者、历史、预览和失效对象均记录并设置保护。最多 100000 个对象，分批复制时验证长度与 SHA-256；正文不进入数据库。

输出包括 `db.sqlite`、`media/objects` 和版本为 1 的 `manifest.json`。清单含数据库摘要、对象描述和 `copied`/`missing` 状态。不可读或损坏的原媒体记为缺失；复制中的其他错误或取消使本次返回失败。最终清单只在全部条目处理完并落盘后发布，没有它的目录不能视为完整备份。如果清单落盘后在线数据库完成回执失败，文件备份仍需独立核验，在线状态不能代替清单。

Linux 发布清单前同步媒体目录及父目录；Windows 使用同卷、不覆盖的 write-through 移动。不将本地磁盘行为推定为 NAS 保证。备份保护暂不自动释放，删除备份不自动清除在线 pin。

恢复测试将快照放入全新数据目录，再读取备份媒体。缺失的已选对象会转为 `unavailable`，保留人工锁；手工内容不一定能重新抓取。配置、凭据、制品校验和管理命令仍由 P8 负责，不能只复制数据库当作完整部署备份。

验收见[统一记录](validation/media-storage.md)与[仓储记录](validation/media-gc-backup-storage.md)。
