# 统一内置插件与自动发现验收

日期：2026-10-10。当前工作区构建，含未提交及并行开发内容；不是签名发布。

## 行为

- 默认构建两个程序：`musicfs`、`musicfs-plugins`。七种内置角色由 `--plugin` 选择；仍分别启动进程，保留已有单插件入口以供兼容构建。
- 发布构建去除调试信息；开发构建保留。配置中的可选 `args` 直接作为参数数组传递，不通过 shell。
- 启动时检查 `pluginBundle`，省略则检查 Server 同目录。发现的内置角色默认启用，插件或实例明确 `enabled: false` 时保持禁用。
- 缺少音乐目录或 FFmpeg/ffprobe 文件时显示 `pending_configuration`，原因为 `CONFIGURATION_REQUIRED`；不会启动工作进程，也不阻止 Server 就绪。
- 管理接口保存配置后可启动就绪的插件；禁用设置持久化并在重启后保留。设置页显示状态、待配置提示及手动刷新，包含四种语言文案。
- 发现范围仅为当前统一程序的内置目录，不代表任意 EXE、DLL 或第三方插件 ID 的自动安装机制；运行中新增程序需重启注册。

## 验证结果

- 配置单元测试、插件管理集成测试通过，包括默认发现、显式禁用、外部入口保持、参数格式、配置保存和禁用持久化。
- 同一个统一程序同时启动网易云、QQ、Apple Music 角色；角色不匹配拒绝握手，关闭一个进程不影响其他角色；缺少/非法角色参数以失败退出且不污染协议标准输出。
- 真实 Server 验证七种角色自动注册：Local Files / FFmpeg 缺配置时待配置，其他角色就绪；禁用 NCM 后重启保持禁用。
- 完整 Windows 安装包 `packages/musicfs-unified-windows` 验证校验清单、WAV/NCM Range、FLAC 解码 PCM 与定位、Web 静态交付及进程退出，通过。
- Web 构建、类型检查及 43 项单元测试通过；Edge 测试验证待配置/禁用/就绪显示、刷新和语言切换，通过。
- Go vet 曾在该轮工作区通过。Linux amd64 两个程序交叉编译通过，本轮未进行 Linux 运行验收。

最终 Windows 包中统一插件为 12,391,936 字节（11.82 MiB）；旧 `packages/windows-start/bin/musicfs-plugin-*.exe` 合计 68.97 MiB，减少约 82.9%。两者业务源码并非冻结在同一版本，最终包已包含工作区新增 SQLite 插件状态存储依赖；该比较反映这两个实际安装包的占用，不作为纯链接选项的基准。统一程序仍为各进程保留独立运行时状态和堆。

## 未通过的扩大回归

整个 `tests/contract/...` 在当前工作区仍有在线账号相关失败：旧匿名搜索、专辑和远程歌单测试收到 `PLATFORM_AUTH_REQUIRED`，部分旧账号隔离样例预期也与新 Schema 不一致。本次统一插件和自动发现的针对性验收通过，不能据此宣称整个工作区全量回归通过。

首次沙箱内测试的本机连接及 Windows 原子配置替换受到权限限制；上述集成和安装验收均在正常本机权限下重新通过。
