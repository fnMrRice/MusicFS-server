# 大库扫描分页快照期限修复

日期：2026-10-10。真实库扫描在逐曲探测期间耗时超过 5 分钟后，继续读取已有快照返回游标过期；该次观测停在 1088 条、326.28s。原宿主快照固定从创建起保留 5 分钟，库扫描总预算为 10 分钟，两者不匹配。本记录不含私人目录、曲目或账号资料。

## 当前边界

- 默认空闲期限为 5 分钟。只有同一 Worker 的有效根目录、游标和未取消请求可以续期；快照内容、根身份与游标不因续期改变。
- 每份快照创建时固定最多 1 小时的总寿命，任何持续请求也不能越过；整次库扫描的上下文预算同时改为 1 小时，取消仍向 Worker 传播。单页处理或暂停超过空闲期限时仍会失败，调用方重新开始扫描，不能拼接新旧快照。
- `pluginhost.Config.SnapshotIdleTimeout` 与 `SnapshotMaxLifetime` 是宿主内部参数，0 分别采用 5 分钟和 1 小时。显式值必须为正、空闲期限不超过总寿命、总寿命不超过 1 小时；它们不是新 YAML 配置字段。
- 每 Worker 最多 16 份分页快照、每次枚举最多 50,000 个候选、每页最多 200 项的限制不变。访问过期快照或创建新快照时清理过期记录，错误或跨根请求不续期。没有无期限续租或后台保活。

## 实际验证

新增 `tests/integration/plugins/scan_lifetime_test.go`，构建并调用真实 Local Files Worker；用两个临时合成 WAV 根目录和两个独立所有者/Worker 验证，期限缩短到毫秒级。没有等待实际 5 分钟或 1 小时。

Windows amd64、Go 1.26.9、当时用户工作区依赖，执行：

```text
go test -mod=readonly ./tests/integration/plugins -run '^TestRealWorkerScanSnapshotLifetime$' -count=3 -v
```

三轮全部通过，测试分别 5.22s、5.32s、5.36s，包合计 16.057s：

| 验证 | 结果 |
| --- | --- |
| 700ms 空闲期限，间隔 175ms 继续分页 | 三轮均持续约 1.14s，跨过最初期限；根身份、条目与页序保持一致 |
| 400ms 空闲期限，中间发送错误根和已取消请求 | 期限之后仍被拒绝；无效活动没有续期；可以重新开始扫描 |
| 600ms 空闲期限、1500ms 总寿命，持续间隔 100ms 请求 | 三轮均在总寿命附近返回 `RESOURCE_CHANGED`，未无限延长 |
| 跨 Worker/所有者、跨根、缺失或畸形 token、超范围 offset | 均拒绝，合法游标继续有效 |
| 0 默认、正值、负值、空闲大于总寿命、总寿命超过 1 小时 | 按配置边界接受或拒绝 |

最初沙箱运行因临时目录不允许插件状态文件原子重命名，在 Worker 启动前失败；之后使用仓库忽略的 `build/_scan-lifetime/tmp`，在提升后的本地环境运行。第一次提升运行的活动分页用例曾遇到一次 10s Worker 请求超时，其他用例通过；未修改源码或延长测试期限，单项重跑及上述完整三轮均通过，超时根因尚未复现。总寿命测量从首个响应返回开始，快照实际创建稍早，不能据日志的小幅时间差推断提前失效。

随后主代理统一回归确认：Windows 完整测试与 race 均通过并覆盖本用例，插件集成包分别 49.798s、45.339s；Linux 完整测试通过并覆盖本用例，插件集成包 86.042s。上述包时间包含其他插件测试，不是 TTL 用例单独耗时。Linux 核心/E2E race 在本记录完成时仍在运行，不提前记为通过。

这些短时真实 Worker 测试验证期限规则；后续冻结源码的双根真实库复验已通过，613.12 秒完整发布 1,943 条来源，并通过重启标识及抽样播放校验，见[真实本地库记录](real-local-library.md)。修复源码在统一回归期间保持冻结，未因首次超时扩大或绕过期限。
