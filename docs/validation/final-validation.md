首次 Windows 完整检查在目录监听测试报错。独立原生探针确认，创建深层文件仍可能改变直接子目录 `child` 的元数据，Windows 非递归监听合法报告 `action=3/name=child`。生产接口只给合并提示，不返回文件名，因此不能据此断言深层操作后绝无提示；生产通知不应被错误过滤。该次失败保留在记录中，不记为完整检查通过。

最终夹具保留 Linux 深层变化无提示的负断言；Windows 用独立空目录验证直接变更正向通知，避免之前的合法子目录提示误满足断言。两边都验证关闭后无回调、句柄绑定、替身拒绝和取消回收。修正用例分别进行 12 次覆盖率和 race 验证通过，整个 Windows 监听包最终 race 通过 4.937 秒；详见[监听记录](scan-watch.md)。生产通知实现未因测试而过滤合法事件。

Linux 首轮完整 E2E 在整个包累计 10 分钟时触发 Go 默认期限，当时写回用例刚运行 19 秒，堆栈位于实际程序构建等待；此前该包已运行用例均通过。Windows 完整 race 的存储包也触发该期限，当时第 116/117 项才执行 2 秒，随后仅补跑最后两项。检查入口现为每包 20 分钟，可用 PowerShell 的 `-TestTimeout` 或 shell 的 `TEST_TIMEOUT` 覆盖；业务请求、扫描和停机期限未改变。分段结果与初次失败均保留，不将退出失败的原命令改写为通过。
