# 真实本地库与 NCM 验收

日期：2026-10-10。使用用户授权的本地目录，只读扫描一个下载目录及其父目录，分别作为同一 Local Files 实例的两个根。记录仅包含汇总结果，不提交目录、曲名、音频、账号、私密响应或测试数据目录。

## 完整扫描与来源标识

完整双根复验使用冻结的 `ac5a09c` 源码，加上 `76818aa` 的扫描期限修复；独立构建、配置与数据目录避免开发中代码改变测试结果。扫描共 613.12 秒，发布 1,943 条来源：父根 1,855 条，子根 88 条。探测结果为 1,417 条 FLAC、526 条 MP3；数量包含两个根中重复观察到的物理文件。

88 个重叠物理文件在两个根中各自保留 ExternalID、SourceTrack 和 SourceAsset，不因内容相同合并出处。同一 YAML 配置重启后，1,943 条来源及资产标识保持稳定。早先固定五分钟快照期限导致的失败和修复见[扫描期限记录](scan-snapshot-lifetime.md)；这次扫描跨过该时间点并完整发布，没有使用失败扫描的部分结果补齐。

## 原文件、播放和定位

抽取 6 个实际文件：4 个 NCM（内部 MP3、FLAC 各 2 个），以及普通 MP3、FLAC 各 1 个。全部经过真实 HTTP 播放、处理后 PCM 校验和 30 秒定位；适用的 MP3 原流还通过完整输出摘要和三个 Range 片段逐字节比较。重启后再播放一个样本通过。

前一轮子根独立验证包含 88 个 NCM，扫描 28.06 秒；4 个 NCM 的处理 PCM 最低相关系数 0.98682，最大定位误差 23 毫秒，在当前 100 毫秒容忍范围内。上述数值仅代表这组样本与当次环境，不是所有文件的性能保证。

完整双根测试前后，6 个样本原文件的 SHA-512 完全相同。测试未写回标签、歌词或封面，未改写或删除音乐文件。处理输出、解密缓存和独立测试库位于忽略的工作目录。真实浏览器与合成 NCM 的既有验证见[Web NCM 验证](../../../web/docs/ncm-validation.md)；本次真实文件测试通过 HTTP、解码及 PCM 测量完成，没有宣称人工扬声器听音或全部网易云客户端下载版本均兼容。

## 正式后台 SHA-512 接口

随后使用 `f703374` 独立源码快照、新配置和新数据目录验证正式任务接口。新版文件版本包含文件变更时间，旧验证库不沿用；禁用音频/NCM 元数据探测后重新观察双根的 1,943 条来源，避免把旧资产版本解释成新版版本。

配置为 `hashing.auto: false`、并发 1、每秒 4 MiB，仅对上述 6 个样本提交 `hash-jobs`。全部返回 `verified`，并与测试前独立计算的原件 SHA-512 相同。4 个 NCM 的正式摘要均不同于其解密载荷摘要，证明完整文件摘要没有被内部音频摘要替代。库中恰好 6 条来源计算了摘要，其余保持未知；该轮共 64.13 秒，结束后 6 个原件再次校验全部未变。

## 验证范围

本记录证明指定 Windows 本地文件系统上的真实目录扫描、独立来源、重启稳定性、抽样播放和正式完整文件摘要任务。物理 NAS、其他客户端下载版本及未经抽样的每一首歌曲仍需各自验证。两次源码快照分别记录，不能据这组抽样声称已对完整音乐库进行了哈希或逐曲播放验收。
