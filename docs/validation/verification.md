# 复验方法

未完成项目见[待验清单](README.md)，素材见[测试夹具](fixtures.md)。常规构建、单元/契约/集成测试和竞争检查使用仓库 `scripts/check.ps1` 或 `scripts/check.sh`；这些脚本同时检查宿主、SDK 与在线插件模块。以下补充不能由常规自动测试代替的验证。

## 环境与结果记录

每次验证固定源码提交或明确标注工作树构建，记录 Server、SDK、插件、Web、OS/架构、文件系统、浏览器、媒体工具的实际版本及可执行摘要。源码构建与安装包运行分开记录。依赖使用锁定版本，独立模块以 `GOWORK=off` 检查。

结果只记“通过、失败、未执行”，列出实际范围、错误与证据位置；分段补跑说明各段使用的代码，不将原失败命令改写为通过。原始日志、音频和临时库放在忽略目录，提交说明只保留可复核汇总，移除账号、凭据、私密路径及私人曲目内容。

真实工具场景需要 `MUSICFS_FFMPEG`、`MUSICFS_FFPROBE`，指纹场景还需 `MUSICFS_FPCALC`；均填写本机已核验的绝对路径。没有工具导致的跳过不是通过。精简 FFmpeg 构建需具备被测编码/解码/封装组件；输入隔离测试还需确认工具本身具备测试所针对的播放列表能力，否则拒绝可能只是缺组件。

Windows 的 ACL、目录联接、文件锁及原子替换测试应使用具备正常权限的独立本地目录。特殊云目录属性或沙箱拒绝必须与产品错误分开记录，不能为使测试通过而放宽生产保护。Linux 记录数据实际位于原生文件系统还是宿主挂载盘。

## 真实平台账号

依据[平台登录](../providers/platform-login.md)的现有用户入口逐平台执行，使用已获授权的测试账号。

1. 完成授权，核对平台身份与当前实例；再测拒绝、取消、过期挑战和风控。网易/QQ 的二维码创建及取消探针仅验证挑战入口，不关闭真实登录项目。
2. 重启后确认账号为待校验，业务查询被拒绝；完成平台校验后再执行该插件声明的业务。
3. 使用两个账号、两个实例及不同 MusicFS 用户，交错读取和分页；验证账号切换、退出与同账号重新登录后，旧缓存、旧游标和迟到响应不能复用。
4. 分别制造临时网络失败与真正认证失效，检查绑定保留、重新授权、权限错误及 MusicFS 会话不被误退出。当前没有自动续期，不能填写“刷新通过”。
5. 对实际支持的搜索、资料、推荐、私人歌单和多页同步逐项记录；观察期间发生增删、重复曲目、半途失败或权限改变时，确认未发布空快照覆盖旧内容。
6. 整曲交付须另有资源授权及资产版本证据；目录资料、试听、推荐或 MusicKit 页面播放不能替代 Server 流式音频验证。

现有挑战探针位于 `plugins/source/online/tests/online/account_live_test.go`，需在在线插件模块设置 `MUSICFS_LIVE_LOGIN_PROBE=1` 后运行 `go test -mod=readonly -count=1 ./tests/online -run '^TestPlatformLoginLiveChallenge$'`。不要记录二维码地址、Cookie 或令牌。遗留 `MUSICFS_ONLINE_LIVE` 用例须先修正登录前置断言，见待验清单。

## 真实播放与定位

每个 OS、浏览器、输出 profile 与物理输出设备独立验收；填写实际输入摘要、源/输出格式、声道和采样率。

1. 低音量开始播放标记音频，人工确认曲目、左右声道、音量和三段位置标记；同时记录从创建请求到首个可解码帧及可闻输出的时间。
2. 原流验证暂停/恢复、首中尾部定位、Range、连续 A/B/A 切歌和停止。处理流确认整曲生成结束前已开始播放，gain 的 PCM 数值与听音分别核对。
3. `timeRestart` 检查新 attempt/representation/URL、曲目时间映射、前导静音及实际定位误差；快速定位、响应丢失后同键重试、定位中切歌/停止均单测。MP3 已用场景的容差为 100 ms，新 profile 不直接继承该结论。
4. NCM 分别测内层 MP3 与 FLAC、损坏容器和恢复；原容器摘要与解密输出摘要分开，不能复用原文件 Range 偏移。
5. 跨源恢复使用独立时间轴证据，资产或处理链变更后重新验证；无证据时应提示从头播放。
6. 另一用户/会话、撤销、过期和重启旧 attempt 均不能访问旧流；停止后核对请求、文件引用、子进程和未完成输出回收。

每个样本记录原文件前后摘要。通过工具解码但未人工听音时，仅关闭工具解码事项。

## 文件系统与恢复

用独立测试目录和合成音频构造根替换、失挂/重挂、慢读取、权限变化、同尺寸覆盖、链接/目录替换竞争和通知丢失。分别核对完整扫描与不完整扫描、范围外旧条目、资产版本、已打开播放和重启后的恢复；不在生产目录进行故障注入。

针对每种目标介质核对 SQLite 锁、文件同步、稳定读取保护和备份恢复。进程终止与硬件掉电分开验收；没有设备证据时保留掉电项目。原件写回遵循[写回边界](../metadata/writeback.md)，只在明确支持的文件系统和文件类型上做正常写入，其他组合验证拒绝及原件保持。

长扫描验证实际空闲期限与总寿命，不拼接不同分页快照。出现 Worker 超时时先保留请求阶段和进程/资源证据，不用扩大期限或忽略失败关闭项目。

## 资源与长期运行

现有 Windows 资源入口使用 32 个合成 WAV，四轮并行摘要/指纹任务、两路原流、两路处理流及慢消费者，取消后观察资源，再完整读取并复用一次处理输出。它是短时观测，不是容量或长期无泄漏保证。

```powershell
$env:MUSICFS_RESOURCE_BASELINE = '1'
$env:MUSICFS_FFMPEG = 'C:\tools\ffmpeg.exe'
$env:MUSICFS_FFPROBE = 'C:\tools\ffprobe.exe'
$env:MUSICFS_FPCALC = 'C:\tools\fpcalc.exe'
$env:MUSICFS_RESOURCE_REPORT = 'build/_resource-validation/windows.json'
go test -mod=readonly -count=1 -v ./tests/integration/resources -run '^TestResourceBaselineActualServer$'
```

替换工具路径并核对执行退出码。部署资源数据使用普通构建；race 插桩的占用单独记录。

- 记录服务及自有子进程的 CPU、工作集、私有提交量、句柄、线程、连接、缓存和持久媒体，按进程创建时刻防止 PID 复用误归属。
- 采样可能漏掉短命进程，不能把采到的峰值当作严格最大值；工作集与私有提交量不能相加，主进程 CPU 不代表整个树。
- 取消后的 `.part` 应回收，完整可复用缓存与持久指纹文件按各自策略保留；继续观察真实闲置与最长保留期限。
- 延长固定负载并逐项归因残留句柄，覆盖当前统一插件、外部存储与 DSP 的实际部署组合；Linux 另采相同负载，不能套用 Windows 数字。

## 安装、代理与升级

安装验收指定 `MUSICFS_RELEASE_ROOT`，执行 `tests/e2e/release*_test.go` 中的真实制品用例；测试必须运行包内二进制，不能重编替代。默认交付为 `musicfs` 与 `musicfs-plugins`，统一程序按角色启动独立进程。

1. 核对完整清单、校验和、许可证、外部工具依赖和默认配置，再复制到干净机器的新目录运行。
2. 验证静态 Web、鉴权、扫描、原流/NCM/处理流、定位、SQLite/DSP、备份恢复和最后租约释放后的退出；按当前配置确认待配置、启用、保存停用与重启后状态。
3. Docker/Compose 使用实际引擎运行，检查只读音乐与持久目录；Nginx/TLS 使用真实代理和远程浏览器，检验证书、Cookie、Origin/CSRF、Range、SSE 和无整曲缓冲的流式输出。
4. 升级前固定备份，验证多客户端协调、迁移失败和恢复入口。独立部署的 Server 不能被客户端自动接管；恢复平台账号后重新校验，失效时重新授权。

具体操作以[部署](../operations/deployment.md)、[备份](../operations/backup.md)和[生命周期](../operations/lifecycle.md)为准；测试成功后只删除相应环境与能力的待验项。
