# 递归范围与隐藏目录过滤验证

日期：2026-10-11。Local Files 的导入声明升级为 `local-import-v5`，默认 `recursive:true/maxDepth:0/skipHidden:true/respectNoMedia:true`。开启递归时 0 表示不限深度；正数 1—64 保留既有层数语义。关闭递归仅覆盖所选根本层，并规范为 0。原有明确指定的正数设置保持不变；旧排队任务仍检查其原声明版本，不会改用新的默认范围。

Windows 定向验证通过：

- 配置逐层合并、YAML 与 JSON Schema、插件声明、HTTP 契约和 OpenAPI 引用均接受开启递归的 0；负数、关闭递归搭配正数仍拒绝。
- 管理 API 保存并读回 `true/2`、`true/0`、`false/0`；音乐目录与排除规则保持原值。
- 实际创建 70 层目录：不限深度枚举到第 70 层文件，64 层扫描不包含第 65/70 层，关闭递归只返回本层文件。真实 Local Files Worker 同样通过第 70 层扫描。
- 文件与目录范围函数共同覆盖 0、1、64、65、1000 层；1000 层为内存路径验证，不计为磁盘测试。排除规则继续适用于不限深度模式。
- 通知注册可获取全部 71 个目录句柄；64 层只注册 65 个，关闭递归只注册所选根。句柄预算超限仍整体失败并回收，不能由不限深度绕过资源上限。
- SQLite 发布验证：已导入第 70 层的记录经过 64 层、本层或排除该分支的扫描后保持不变；只有覆盖该深度的不限深度完整扫描才会把消失的文件标记缺失。
- 真实 HTTP 服务从关闭递归切换为开启且省略深度，返回有效深度 0 并导入第 70 层文件。后续浅层扫描保留深层记录；原生文件通知、重启补漏和默认关闭回归通过。

验证命令覆盖 `tests/unit/config`、`tests/unit/plugins`、`tests/contract/plugins`、`tests/contract/api`、`tests/integration/storage`、`tests/integration/plugins` 中递归/范围/契约相关测试，以及管理 API 与两项扫描/通知端到端测试。相关包 `go vet` 通过；Linux amd64 Server 交叉构建通过，未计为 Linux 运行验证。

一次旧管理测试在受限沙箱中无法复制临时 YAML 的 Windows ACL；使用正常权限重跑后通过。不涉及修改用户部署文件或系统目录权限。

## 隐藏条目与 .nomedia

同日新增过滤项的 Windows 验证通过：

- 默认跳过点前缀文件/目录、实际设置 `FILE_ATTRIBUTE_HIDDEN` 的文件/目录，以及含 `.nomedia` 的目录和后代。标记存在性通过 `Lstat` 检查，目录类型的 `.nomedia` 也生效，不读取标记内容。
- 显式选中的点前缀或 Windows 隐藏根本身允许扫描；所选根内存在 `.nomedia` 时整根不扫描。只检查所选根及其后代，不搜索根以外的祖先标记。
- 点前缀和 Windows 隐藏属性的符号链接先被隐藏过滤，不阻断正常扫描；可见符号链接仍产生原有不完整扫描问题，不跟随到根外。这些符号链接测试实际执行通过，未跳过。
- 深度和静态排除先于属性及 `.nomedia` 检查。Windows 独占锁定未选层级的子目录后，本层扫描仍成功；开启递归包含该目录时夹具确实报告无法读取，证明过滤不会探查范围外目录。
- 两个开关可分别关闭。管理 API 返回明确的 `false` 值，避免界面误恢复默认。旧 v3 计划固定 JSON 的摘要与原值一致，省略字段继续表示旧的不过滤行为；新开关进入计划及分页授权绑定。
- 动态排除范围只来自 Host 文件系统快照，不经 Worker wire。Host 校验观察条目、版本、分页、完成状态与实际交出内容一致；伪造隐藏观察、缺项、额外条目或游标均拒绝。SQLite 拒绝缺少 Host 范围证据的过滤扫描，保留被隐藏或标记排除的旧曲目、当前资产及身份。
- 真实 HTTP 服务先按默认只导入普通音乐；显式关闭过滤后导入全部。随后移除普通文件、点文件、Windows 隐藏目录内文件和标记目录内文件；默认扫描只将普通文件标记缺失，排除分支记录保持可用。删除 `.nomedia` 后只恢复该分支对账，显式关闭隐藏过滤才对隐藏来源确认缺失。
- 监听保留 `.nomedia` 所在目录自身，停止注册其后代。真实 Windows 通知验证根标记删除后自动导入、重新添加标记并删除音乐后扫描保留记录、再次删除标记后自动确认缺失。该测试通过用时 3.00 秒；不等待 30 秒周期补漏。

新增针对性测试包括 `scan_filters_test.go`、Windows 属性与符号链接测试、Host `scan_receipt_test.go`、SQLite 过滤范围集成测试，以及两项真实 Windows HTTP/通知回归。`src/plugins/pluginhost`、`tests/unit/plugins`、`tests/unit/config` 全包测试通过；过滤项与递归相关合同、集成测试通过。相关源码 `go vet` 与 Linux amd64 Server 交叉构建再次通过；仍未运行 Linux 端到端测试。
