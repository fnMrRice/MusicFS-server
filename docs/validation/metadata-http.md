# S-P6-03 本地补全接口验收

2026-10-10，在 Windows 使用当前已提交依赖、`go test -mod=readonly` 和隔离的测试目录验证。源素材为仓库合成 WAV/MP3，测试内生成 ID3 USLT/APIC、2×2 PNG、旁置歌词和 NCM 容器；没有私人歌词、商业音频或外部内容请求。

## 定向结果

- 配置加载、Schema与正式 YAML 示例：最终1.710秒通过。
- 插件真实 DTO 与 `scrape.search/fetch`、专用握手契约、非法通道/私有路径/正文拒绝：最终1.065秒通过。
- 新 HTTP 模型、全部正反样本和 OpenAPI 引用/CSRF/幂等声明：首次2.578秒通过；增加真实 SQLite 所有者隔离检查后，最终4.163秒通过。其他所有者的任务读取、取消、候选应用和实例选择均404，本人实例列表不泄漏其他实例。
- `TestMetadataActualServerCandidatesApplyCancelAndRestart`：15.86秒通过，包总计16.963秒。包含重新启动时禁用 Scraper 的第二阶段。

实际 YAML Server 验证内嵌 `zho→zh` 歌词与旁置 `und` 歌词并存、封面语言为空、格式与正文校验、损坏旁置候选 unavailable、扫描后来源被删除导致单目标 failed 而其余目标继续。候选列表不泄漏资源票据、路径或内部代次，预览不改变选择。逐字段选用使用修订0→1→2→3并加锁；旧修订409，取消后新应用409，原成功键仍重放。指定未匹配语言没有伪造候选，真实 NCM 解密后可提取内嵌内容。

任务创建覆盖重复/不存在来源、未知/停用/排除全部实例、null列表、伪造资源与不支持的查询修正；会话、CSRF、Origin按既有规则拒绝未授权请求。停用 Scraper 后同库重启，历史任务、预览正文、当前选择和人工锁仍可读取，新任务明确失败。播放回归使用同库已知 WAV 的实际 Range 和停止；所有未被测试主动删除的音频及旁置文件 SHA-256保持不变。

首轮验收将损坏 NCM 误预期为目标失败；实际实现保留旁置机会并返回 completed + UNSUPPORTED 问题，测试改为真实删除来源检查 failed。未配置 ffprobe 时带 ID3 的 MP3 没有已验证播放格式，播放请求正确返回415；因此本步骤播放回归用已知 WAV，不修改播放策略、不声称 MP3解码已由本次测试验证。

本记录不代替完整跨平台/race验收，不包括浏览器补全界面、人工听音、自动补缺、远端抓取或写回。Windows进程、loopback及原子文件发布在已授权环境运行，临时目录位于仓库忽略路径；其他平台按单独真实结果记录。
