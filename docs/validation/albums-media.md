# P6 补齐：专辑、派生文件与专辑任务

日期：2026-10-10。本步骤补齐 S-P6-01 的来源专辑/发行独立封面、缩略图和完整刮削文件，以及 S-P6-03 的来源专辑事务展开。用法见[专辑](../albums.md)与[派生媒体](../derived-media.md)。没有扩展最简 Web 或动态插件管理。

## 实现与定向证据

- 来源专辑、发行及独立封面拥有分离的修订和人工锁。实际图片文件校验、同用户/实例成员授权、成员上限、逆编号顺序保留、重排、幂等和发行依赖修订均有真实 SQLite 验证。最终专辑单元/存储 race 分别6.507/20.354秒。
- 来源专辑任务在入队事务固定成员、当前资产和媒体选择修订。原请求重放不重新展开，旧成员修订的新请求冲突。HTTP/数据库重启/真实组合结果见[接口记录](albums-http.md)。
- 缩略图以原对象编号、实际摘要和固定转换版本复用，真实解码验证尺寸/透明度、不放大小图。覆盖 published 未引用及 referenced 未完成后的恢复、文件损坏与新对象重建、全部历史备份、GC保护和原来源归属复核。最终 storage 定向 race 12.622秒。
- 真实 Scraper Worker 保存完整结构化搜索和逐候选取回结果，包含全部目标快照、插件握手版本和文件对象引用。独立 Schema 验证实际 JSON；断言没有资源访问票据、原目录或歌词正文，数据库只含派生描述。最终真实 Worker 文档与归属检查 race 13.198秒。
- 真实服务覆盖专辑/发行封面、按专辑任务、文档、PNG、禁用 Scraper 后重启历史读取、Range播放/停止；所有音频及旁置文件字节不变。定向 E2E race 13.566秒。

## 全量验收

Windows 完整格式/静态/覆盖率检查通过，随后全量 race 通过（E2E 168.122秒、存储270.295秒、写回宿主48.438秒）。首次 race 发现已提交写回在释放文件保护时短暂误报 recovery；修复为执行中的收尾仍返回 running，真正中断保留 recovery。通过可控的提交后暂停用例和三轮真实恢复/服务回归（43.351/36.120秒）后，重新完成全量 race。

Linux 使用 Arch WSL2、Go 1.26.9、实际 FFmpeg/ffprobe 6.1.6；全源 vet 和15个关键包 race通过（真实插件282.230秒、存储186.944秒、E2E399.648秒）。写回状态修复后再次通过全源 vet、library15.471秒、writeback1.053秒及HTTP54.214秒。Linux原件写回仍明确拒绝，不能据此推定Linux/NAS可安全写标签。
