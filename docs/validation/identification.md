# P5 资产识别验收

## S-P5-01：证据字段与失效模型

日期：2026-10-10。当前实现见[资产识别说明](../identification.md)。本步建立证据及任务发布边界，实际后台 SHA-512 计算、指纹、候选和人工关联分别属于后续步骤。

| 检查 | 证明的行为 |
| --- | --- |
| 证据模型与值校验 | 未知码率/摘要为 null，已知零大小与未知不混淆；零码率、音质名称冒充模式、错误摘要、部分字节范围、未来时间及 Provider 冒充 verified 均拒绝 |
| 申报与探测 | Provider 原申报独立保留；实测、估算、人工来源分开，模式没有证据时为 unknown；人工值不被扫描覆盖 |
| 同资产重新扫描 | 保持稳定来源、资产及相同证据 ID；成功探测协调本轮缺失/来源切换，失败探测保留此前成功结果；不清除有效完整文件摘要 |
| 任务版本与代次 | 更换标签/音质版本、来源消失、后发任务、算法/配置变化、取消及篡改范围后，旧结果不能发布 |
| 原子性与并发 | 同时开始/发布只有当前代次生效；插入失败回滚旧证据与当前投影，不出现半次更新 |
| 持久与审计 | 摘要以 64 字节保存；历史证据保留并按用户分页，当前投影排除失效证据；跨用户读取及发布拒绝 |
| 固定分页 | 证据变化推进 libraryRevision，旧游标仍读取它原来的证据快照 |
| 真实 HTTP | 返回的 SourceTrack.asset 通过 Schema；unknown、pending、failed、unavailable、verified 与换资产流程正确，响应不含私有路径 |
| 真实 VBR 文件 | 实际 ffprobe 证据进入扫描结果；没有 SHA-512 仍可原流播放与精确 Range；相同文件重扫不新建证据 |

真实 VBR 用例使用项目已有合成夹具，不能据其通过宣称所有真实歌曲、所有 VBR 格式或在线 Provider 已验收。摘要写入测试直接调用受信任发布接口验证事务，不冒充后台读取或算法计算。

版本证据来自本次 ffprobe 输出；包含发行后缀、空白或超出标识长度的版本字符串采用原始字符串的 SHA-256 标识。测试包含带 `+` 的发行版本，避免证据校验意外阻断可用探测器。

### 统一回归环境

Windows amd64 / Arch WSL Linux amd64，Go 1.26.9；使用已提交依赖快照的 `GOFLAGS=-mod=readonly -modfile=...`，没有将工作区用户另行更新的依赖或导入格式纳入本步骤。Windows 工具为 FFmpeg/ffprobe 6.1.1，Linux 为本地构建 6.1.6，来源与摘要见[配置音频验收](configuration-linux-audio.md)。

- Windows `scripts/check.ps1 -Race` 完整通过：格式、vet、全部带覆盖率测试及全部 race；E2E 普通 51.669 秒 / race 33.468 秒，插件集成 38.818 / 22.381 秒，存储 14.284 / 11.826 秒。真实工具均已配置。
- Linux `go vet ./src/... ./tests/...`、`go test -count=1 ./tests/...` 全部通过；E2E 113.236 秒、插件集成 79.232 秒、存储 0.213 秒。没有用交叉编译替代运行测试。
- Linux 追加 `go test -race -count=1 ./tests/unit/identification ./tests/integration/storage ./tests/contract/api ./tests/e2e` 通过，分别为 1.041、3.790、6.122、91.930 秒。

## S-P5-02：后台完整文件 SHA-512

日期：2026-10-10。新增手动创建、状态和取消接口，YAML 自动选入、独立有界队列、共享限速、持久任务恢复与冲突审计；没有隐式下载在线音频。详细接口专项记录见[哈希配置与 HTTP](hashing-api.md)。

| 检查 | 结果 |
| --- | --- |
| 完整原始字节 | 空文件、`abc` 标准向量、多 64 KiB 分块、带标签与封面的 NCM 原始容器均匹配独立 SHA-512；短读、额外字节、读取变化和发布前变化均不能 verified |
| Windows 实际保护 | 共享读取保护拒绝已有写句柄/可写映射及新的写入/替换；普通句柄关闭后保护仍有效；取消释放保护，恢复 mtime 的同尺寸写入仍改变资产观测版本 |
| Linux 实际保护 | 原生临时文件系统读租约通过；写入意图使结果失效并迅速释放，已有可写映射不能取得租约，路径替换被拒绝，短发布事务内持续保护 |
| 队列与发布 | 并发提交合并、自动关闭/开启、并发上限、共享速率取消、扫描并行、shutdown/restart、持久 DB 重开及新 ticket/代次通过；篡改目标/算法/范围或旧任务结果被拒绝 |
| 申报冲突 | 实际摘要以 64 字节保存，错误申报独立审计；改正、撤销及资产替换后当前冲突消失，历史保留；仅实际 verified 值用于同用户字节匹配 |
| HTTP 与播放 | 实际 YAML/Local Worker/HTTP 验证完整 WAV、空文件、取消、重试、原流与 Range；后台任务不会阻断已授权播放；没有路径或跨用户结果泄漏 |

统一回归继续使用前节已提交依赖快照与真实 Windows/Linux 音频工具。Windows `scripts/check.ps1 -Race` 全部通过：常规 E2E 62.997 秒、插件 49.798 秒、存储 30.658 秒；race E2E 57.225 秒、插件 45.339 秒、存储 27.095 秒。Linux `go vet` 及全部 `tests/...` 通过：E2E 121.822 秒、插件 86.042 秒、存储 2.952 秒；SourceAccess 真实租约/发布/取消定向 race 1.117 秒通过。测试含同期大目录扫描有效期修复。

随后用户明确要求一并提交 import 顺序调整与依赖升级，因此对最终 `yaml/v3 3.0.5`、`x/sys 0.49.0`、`x/text 0.43.0` 再次完整验收，未修改这批用户变更的内容：

- Windows `scripts/check.ps1 -Race` 全部通过，race E2E 67.171 秒、插件 27.431 秒、存储 20.340 秒。
- Linux `go vet` 与全部 `tests/...` 通过，E2E 123.833 秒、插件 88.644 秒、存储 3.074 秒。
- Linux 核心追加 race 通过：识别单元 1.040 秒、存储 11.605 秒、HTTP 契约 7.883 秒、E2E 113.724 秒；升级 x/sys 后的真实租约/源保护 race 1.122 秒通过。

上述不证明 NAS 或 macOS 具备稳定读取保护；不支持时返回 unavailable。实际私人 NCM 样本测试另行记录，只公开汇总，不提交原件、文件名、歌词或账号信息。没有把测试替身的完整字节校验冒称为所有存储类型的快照保证。

## 契约影响

尚未上线的 v1 开发基线直接增加必需 `SourceTrack.asset`，插件观测增加必需、可空的 `bitrateMode` 与 `providerSha512`。旧版本兼容不在范围内。总体架构已有 SourceAsset 与独立证据语义，无需改变播放协商；最简 Web 允许新增响应字段且继续使用原有投影。没有新增复杂 Web 页面、插件动态启停或公开历史审计端点。
