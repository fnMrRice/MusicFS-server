# 媒体回收与备份存储验收

范围：S-P6-02 的 SQLite 接口和持久状态。真实文件复制、清单发布、目录同步及恢复由 `mediastore` 文件服务另行验收；本文不把接口测试当成文件系统崩溃测试。

## 回收约束

- 只从已登记的 `aborted` 发布记录创建任务；未登记文件、目录扫描结果和用户文件名不能进入删除接口。
- 只有超过调用方宽限截止时间的记录可被认领。SQL 先筛选，Go 再按完整时间精度核对，避免时间字符串的小数位长度绕过宽限期。
- 每批最多 128 项。所有 `media_content_objects`、所有指纹索引和备份 pin 都保护对象，包括未选用预览、失效索引、历史绑定及人工内容。
- `claimed` 任务持久保存。执行删除前在同一数据库事务内重查引用和 pin，文件删除回调与 `deleted` 回执提交也处于该事务范围。
- 文件已删除但回执未提交时，任务保持 `claimed`；再次执行要求删除回调把文件不存在当作可重复完成。已提交的 `deleted` 不重复执行回调。

## 备份约束

1. 先登记 `preparing` 意图，再向新建私有备份目录内的 `db.sqlite` 执行 SQLite 快照。目标文件必须不存在，已有文件及符号链接都不能覆盖。
2. 快照以只读、不可变模式打开，验证当前 schema 版本、`integrity_check`、外键和媒体引用一致性。不会通过正常数据库打开入口对备份执行迁移。
3. 对象清单只从这份数据库快照读取。包含全部已引用内容和指纹文件，包括历史版本、未选用上传、不同用户对象及已知不可用文件；不从稍后变化的在线库拼接清单。
4. 读取最多 100000 个对象，遇到第 100001 个即拒绝，避免在文件服务检查之前无界累积。对象描述保存为 `pending` pin 后，备份进入 `prepared`。
5. 文件服务逐对象记录 `copied` 或 `missing`。所有对象都有终态回执后才允许完成备份；`missing` 数量明确保留，不能宣称文件齐全。
6. pin 在本步骤持续保留。没有实现删除备份或解除 pin 的入口。对象正文不进入这些表，数据库只保存对象描述、摘要和状态。

同一 ID 与目录的 `prepared`/`finished` 请求可读取原结果。创建快照中断后保留 `preparing`，重试明确要求新 ID 和目录，不猜测半成品数据库是否完整，也不覆盖它。

创建数据库快照与写入 pin 之间，当前回收规则仍排除全部历史引用，因此不会删除已纳入快照的对象。后续若允许删除历史引用，必须重新设计这段协调，不能直接放宽回收条件。

## 自动化覆盖

`tests/integration/storage/media_gc_test.go`：

- 宽限期、历史指纹、未选用预览和备份 pin 的保护；认领后新增 pin 会阻止回调。
- 删除文件后模拟退出，重开真实 SQLite，再次认领相同任务；并发收集者只执行一次已提交的删除。
- 时间纳秒边界和批量上限。

`tests/integration/storage/media_backup_test.go`：

- 从独立只读数据库核对对象 ID 清单；快照后的新增上传不进入原清单。
- 历史人工内容、未选用预览、失效指纹和不同用户的对象均保留；对象缺失显式记录。
- 分页、完成条件、重复结果、pin 持久状态；读取描述不会修改数据库快照字节。
- 已有目标不覆盖，中断意图不复活，schema 或媒体引用不一致时拒绝。

定向命令：

```text
go test -mod=readonly -buildvcs=false -race ./tests/integration/storage -run 'TestMedia(Garbage|Backup)' -count=1
go vet -mod=readonly -buildvcs=false ./src/storage/sqlite ./src/mediastore/...
```

Windows 定向普通测试通过（2.948 秒），定向 race 测试通过（16.054 秒）。双平台整体验收结果由本步骤收尾记录补充。
