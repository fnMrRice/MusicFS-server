日期：2026-10-10。配置、API、持久任务、来源读写协调、原文件替换、稳定来源映射和新资产发布已接入真实 Server。使用方法及边界见[写回说明](../writeback.md)，模块与 HTTP 细节见[模块记录](writeback-module.md)和[HTTP 记录](writeback-http.md)。

## 范围与验证

- 默认关闭；显式授权实例、音乐根和字段，HTTP 只接受当前选择的歌词/封面引用，不能传入磁盘路径或任意标签正文。覆盖已有字段另需配置与请求同时明确允许。
- 实际写入限定 Windows 固定本地 NTFS、单链接普通 FLAC。Linux、网络盘、只读根及不能证明保护能力的文件拒绝写回，独立歌词/封面仍可用。替换语义为 recoverableReplace：保留同目录原件备份，不宣称两次改名合起来是单次原子替换。
- 扫描、摘要、刮削和整个播放会话持有来源读租约；写回延后至活动读者退出。恢复屏障阻止扫描把中间状态识别为新曲目。
- 真实 FLAC 经 HTTP 写回后产生新 SourceAsset、重新探测和 verified SHA-512，SourceTrack/Recording 保持；所有当前人工内容绑定及锁迁移至新资产，包括本次未写回的字段。解码 PCM 与写回前一致。
- 真实 Local Worker 与 SQLite 注入 written 后、数据库提交后但 journal 未完成、进程重启三种恢复边界；显式恢复异步排队，启动恢复先于其他后台任务。旧幂等请求可重放最终结果，恢复后重新扫描曲目标识稳定。
- 全量并发验收发现“journal committed 已返回成功，但来源保护尚未释放”的短窗口。完成视图增加同一 job 的屏障/独占租约检查，GET 与恢复响应均遵守；修复后完整重跑通过。未通过延时测试或放松来源保护隐藏问题。
