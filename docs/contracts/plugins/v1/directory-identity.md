# 目录来源稳定身份协议

`library.rebind.stable-paths-v1` 是目录 Provider 的可选能力，由 `sdk/directoryidentity` 定义。声明该能力意味着采用下列状态格式，允许宿主在原件被安全替换后保持来源曲目身份。它不授予写文件权限，也不是公开 RPC。默认 Local Files 和其他可信注册实现使用同一协议。

未声明该能力的 Provider 仍可扫描、解析资源和声明 `library.packages`。宿主不解释它的身份状态，也不允许它进入原件写回任务。作品包观察的 `externalId` 和 `sourceRef` 是独立的不透明文本标识，各限制为 256 字节，不要求相等或采用十六进制生成规则。

## 状态结构

协议状态位于现有实例隔离的 `host.state.*` 空间，沿用 `StateValue` 的修订号和 JSON 值。

| 键 | 值 |
| --- | --- |
| `AliasKey(rootId, fileIdentity)` | `{"paths":{"相对路径":"externalId"}}`；键编码为 `aliases-` 加上 `rootId + ":" + fileIdentity` 的 SHA-256 小写十六进制摘要 |
| `TrackKey(externalId)` | 完整 `pluginproto.Observation`；键编码为 `track-` 加来源 ID |

此能力的来源 ID 使用 `[a-z0-9_-]{1,74}`，保证状态键有界且无路径语义；该限制不适用于其他 Provider 能力。每个文件身份最多保留 1024 个已观察路径，硬链接路径保持各自的来源 ID。`SourceRef` 不随文件身份重绑定而改变。

## 重绑定和恢复

宿主在任务排队前和取得实例排他租约后检查能力。执行前还核对授权根身份、相对路径、新旧文件身份与版本，以及新文件只有一个硬链接。插件不能直接提交重绑定请求。

SDK 的 `Prepare` 只读取状态并产生三项变更：建立新文件身份的路径映射、更新原来源观察、移除旧文件身份中的该路径。目标身份必须为空，旧映射和观察必须属于当前来源与旧版本。替换后清除依赖旧字节的 Provider SHA-512 和码率证据，保留不透明来源引用。

宿主在首次写入前调用 `ValidatePlan`，校验三项键、顺序、完整前后值和递增修订；随后先持久化意图，再发布状态。未完成意图阻止该实例继续扫描、观察、解析资源及访问一般状态，直至同一可信任务恢复完成。恢复仅接受原状态或计划中的精确新状态，拒绝其他冲突修改；已完成请求重放还会检查实际映射。

`host-rebind-*` 是宿主保留键，插件 RPC 不能读写。没有声明此能力时，宿主不会将既存同名文件解释为恢复日志。协议升级须使用新的能力版本，不按插件 ID 或猜测私有状态布局启用迁移。
