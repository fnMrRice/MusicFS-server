# Web 页面所需的后续接口能力

核对日期：2026-10-10。由 Web 页面开发交接给 Server；用户要求接口由 Server 侧设计。本文只记录页面需求和当前缺口，不定义新路径、请求字段、响应 Schema，也不改变已有 OpenAPI。

依据：[Web 开发方案](../../web/docs/react-development.md)、[搜索设计](../../docs/ui-search.md)、[曲目列表设计](../../docs/ui-tracks.md)、当前 `docs/contracts/openapi.yaml` 与 `http.schema.json`。

## 1. 搜索缺口（优先）

当前已经存在 `GET /online-instances/{id}/search`，只返回在线曲目资料；Web 按实例独立调用，保留来源顺序和部分失败，不把它当作四类统一搜索。`OnlineTrack.playbackAvailability` 当前为 `unknown`，在线解析尚不支持音频播放，搜索命中不等于获得播放权限。

| 页面需求 | 当前缺口 | Server 设计时需明确 |
| --- | --- | --- |
| 本地／NAS 曲目关键词搜索 | `/source-tracks` 仅支持实例、limit、cursor | 完整音乐库关键词匹配范围、查询快照与游标失效、排序规则；不能仅过滤当前已加载页 |
| 专辑搜索 | `/source-albums` 是来源专辑浏览，不是关键词搜索 | 来源隔离的专辑身份、名称、歌手、封面引用、独立分页、可进入详情的能力 |
| 歌手搜索 | 尚无独立歌手搜索／详情契约 | 来源隔离身份、头像、关联专辑／曲目分页；不得从一页曲目临时去重充当完整歌手结果 |
| 歌单搜索 | 推荐、本人歌单和远程歌单观测不能替代关键词搜索 | 平台／个人范围、创建者、封面、来源身份、总量未知与分页、预览与导入的边界 |
| 四类搜索能力展示 | 在线能力只声明 `search.tracks` | 各来源对四种结果类型的可用性、账号要求、权限、暂时离线与未实现的区别 |
| 全部来源搜索 | 当前 Web 按实例分区调用 | 若设计聚合接口，须保留各来源原始顺序、独立游标／错误／结束状态，不混排不可比较的相关性分数 |
| 播放全部搜索结果／加入队列 | 缺少固定查询结果解析；在线曲目暂无播放授权 | 完整结果集的稳定来源引用、修订、取消、不可用项与数量未知语义；不能只播放前一页却称为全部 |
| 查询状态恢复 | 本地查询暂缺，在线游标有过期窗口 | 前进后退与重连后如何重新取得同一查询；失效须明确提示刷新，不混合旧查询结果 |

前端保留曲目、专辑、歌手、歌单四个页签和来源筛选。当前曲目页签接既有在线搜索；其他三类保留界面及待支持说明，不发出猜测请求、不生成假结果。关键词输入和来源选择不依赖未来接口结构。

## 2. 其他页面依赖

| 需求 | 当前边界／缺口 |
| --- | --- |
| 曲目分类与组合筛选 | 缺少全库歌手／流派／目录分类、格式、仅收藏、仅可播放、关键词、完整排序；Web 保留入口并禁用未支持条件 |
| 专辑列表 | 已有来源专辑浏览和详情，Web 可接；封面选用需按受鉴权引用处理 |
| 个人收藏和最近播放 | 未发现读写契约；需定义用户隔离、事件触发时机、去重、删除、分页与保存期限；Web 只留页面，不默认用本机数据替代账号数据 |
| 歌单曲目展示 | 聚合快照仅含来源引用和 provenance；缺少批量获取本地／远程曲目展示信息的读取能力。当前 Web 本地引用需遍历固定修订曲库进行关联，较大库效率差；远程引用保留不可播放说明 |
| 在线歌单详情 | 观测仅返回曲目 external ID；需可分页展示标题、歌手、时长、来源与可用性，不能把逐首查询大量在线资料当成默认方案 |
| 用户资料 | 当前只有真实用户 ID 和角色；无昵称、头像接口时 Web 使用默认图形，不伪造资料 |
| 账号搜索记录 | 可由 Web 以实例／用户隔离的本机偏好实现；跨设备同步如果需要，须由 Server 明确契约 |

推荐、个人歌单创建／改名／聚合编辑／快照、远程导入／同步已有接口。本文不把已有接口再次列为“缺失”，也不要求本轮开发 Server 实现。

## 3. 对接验收要求

1. Server 先设计并发布 OpenAPI 和单一 Schema，明确权限、能力、身份、版本、分页、错误和兼容边界；Web 随后更新适配器。
2. 覆盖无结果、无权限、离线、限流、部分来源失败、追加失败、旧查询晚到、游标过期、未知总数。
3. 曲目／专辑／歌手／歌单同名不能作为跨来源合并依据；可播放性与资料可见性分别表达。
4. 真实端到端验收后再将等待中的界面标记为已实现；Mock 测试只证明页面行为。
