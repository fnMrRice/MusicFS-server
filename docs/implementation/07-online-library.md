## 2. 实现步骤

### S-P7-01：每个平台先交付能力调查

1. 为平台建立能力矩阵：匿名搜索、账号登录、曲目资料、歌单读取、推荐、音质/权限、可交付音频、刷新/限流和分页版本保证。
2. 查看开源接口实现和官方文档，记录实际参照 tag/commit、查询日期、许可、用途；源码复制、修改或分发前核对对应版本及依赖许可。
3. 本期优先用 Go 实现选定适配接口；若选用 Node/Python 服务包装，明确增加的运行时、部署和维护责任，不把它作为无声明的隐式依赖。
4. 使用授权测试账号、公开内容或脱敏录制响应验证；不提交登录 Cookie、开发者密钥、真实私人歌单和可复用音频授权 URL。
5. 只为验证通过的能力宣告 supported。接口不可访问、维护中或能力不明确时记录失败证据/降级行为，不声称已支持。

平台调查不能跳过：Apple Music 的目录/用户数据 API 与 MusicKit 播放授权不同，不能据目录查询成功假设存在可供 Server 转码的完整裸流；网易云/QQ 的推荐和歌曲可播放权限也分别判断。

### S-P7-02：账号、元数据与音频资源

1. 账号绑定 userId、Provider 实例和 accountId；密钥经宿主授权范围提供，插件角色间不隐式复用凭据。
2. 统一映射 externalId、来源版本、质量、codec/container、时长、码率、到期时间与未知值；不可得完整 hash/fingerprint 不阻塞授权播放。
3. stream.resolve 返回受控资源描述和必要的私密头，Host 执行地址/重定向/网络访问校验，客户端不直接获得平台账号凭据。
4. 只在允许客户端直接访问且无需私密凭据时返回直放；其他按 Gateway 能力代理或处理，不把代理当绕过平台授权。
5. 凭据过期、地区/订阅限制、歌曲不可用、限流和网络失败分别映射，不统称 404；缓存状态不能假装当前账号仍有权限。
6. Apple Music 首期可仅声明已验证的 metadata/playlist 能力；无法进入当前统一流管线时 stream.resolve 返回明确不支持。引入 MusicKit Web 播放须先扩展公共契约与 Web 适配，不偷偷塞入未经设计的 deliveryMode。

测试：脱敏响应契约、错误码映射、账号互换、私密头不出 API、资源到期、重定向、质量变化。验收：授权实机探测与离线 fixture 测试分别记录。

### S-P7-03：推荐歌单

1. Provider 可选声明 recommendations.playlists，区分匿名/个性化、实例与账号作用域。
2. 按平台分页返回来源歌单 ID、平台排序、推荐说明、更新时间/有效期和 nextCursor，不自行伪造统一推荐分数。
3. 缓存键包含 user/instance/account/请求配置，登录变化使对应缓存失效；匿名和个性化不能混用。
4. 某个平台失败允许其他来源返回成功，并明确 stale、lastSuccessAt 和错误。
5. 打开推荐项按需读取，用户明确导入/绑定才入个人库；推荐列表变化不删除已导入歌单，不触发平台写回。

测试：无账号、已登录、凭据失效、多用户缓存、分页重复、部分失败和导入后推荐消失。验收：推荐“能看到”不冒充曲目“能播放”。

### S-P7-04：远程歌单的保守同步

1. 固定远程快照版本（若平台提供），完整分页到暂存区，验证页/版本/去重规则后再发布本地 revision。
2. 无一致版本保证时，即使分页结束也不立即删除缺失条目；标记 suspectedRemoved，保存观测代次和复核证据。
3. 后续完整同步或独立查询证实后才移除该来源贡献；分页失败、超时、凭据失效保留上次成功快照。
4. 同歌单同步合并/串行化，保存任务代次；发布事务再次校验有效代次和预期绑定规则，旧任务不能覆盖新结果。
5. 清晰表达 stale、lastSuccessAt、错误和待复核状态；界面不把所有失败解释为远程空歌单。

测试：分页期间增删、循环 cursor、重复页、版本变化、半途失败、复核冲突、旧任务恢复后晚发布。验收：不误删，且存在可完成的复核/清理路径。

### S-P7-05：聚合、出处和隐藏

1. PlaylistBinding 保存稳定引用/顺序/约束，拒绝循环。聚合快照记录规则修订与引用的子快照修订。
2. 默认按 binding 顺序和原条目顺序组合，确认同 Recording 去重，未知按 SourceTrack 去重，保留全部 provenance。
3. 删除一个 binding 只移除其贡献；仍有其他出处则保留条目。本地追加用独立 binding，编辑不自动写远程平台。
4. 隐藏规则独立于快照：默认整首 Recording 全来源，允许 binding/entryId 单出处。未匹配时保留 SourceTrack 原始目标。
5. 匹配/拆分后根据原始目标迁移或保留隐藏意图，歧义提示确认，不能扩散到所有拆分结果。
6. 编辑使用预期 revision/If-Match，分页固定快照，冲突与过期显式报错。

测试：多出处去重/删除、来源重新匹配、错误合并解除、全曲与单出处隐藏、快照重建、并发规则编辑与循环。验收：重建后用户意图和追溯关系不丢失。

### S-P7-06：有限恢复与独立时间轴证据

1. Resolver 对每个候选重新检查用户权限、可用性、质量和处理能力；不能因匹配到 Recording 就获得别的账号资源。
2. 恢复预算包含同源刷新、不同来源数（最多 3 个）和故障链总时间；重复请求或新 attempt 不重置总预算。
3. 同源输入/输出完全未变才可保留有效偏移；输入/表示改变返回新尝试和地址，Web 丢弃旧缓冲。
4. 跨源自动续播要求同 Recording、独立时间映射证据绑定两端资产且覆盖目标位置、目标处理链可定位。指纹或相同时长不能直接生成证明。
5. 尚无可靠时间轴验证器时保持人工/已验证证据入口，默认 promptRestart；不能为了演示自动恢复而填造映射。
6. 构造已知对齐与不同前导静音/裁切样本，分别测试能续播与必须提示重播的分支；歌词同步使用当前来源/映射。

## 3. P7 完成门槛

- [ ] 每个平台都有已核实能力、许可/版本参考和未支持部分，实际在线验证不由 mock 替代。
- [ ] 推荐账号隔离、失效状态和显式导入语义通过。
- [ ] 不一致分页保守移除、代次、出处和隐藏回归通过。
- [ ] 有效/无效时间轴样本能产生正确恢复决定，无无限换源。
- [ ] 最小 Web 仍可本地播放；平台特有 UI 或完整管理台是后续工作，不冒充本期完成。
