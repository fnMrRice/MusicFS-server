# P8：测试矩阵、打包、部署与交付

状态：原阶段八程序安装制品、Windows/Arch WSL2新目录运行、直接TLS、离线完整备份恢复及Server生命周期协议已有实现与实测；当前默认收敛为 Server 与全量统一插件两个程序，见[统一插件验收](../validation/unified-plugins.md)。Windows四轮并行后台任务/慢消费者/输出缓存资源基线已有记录。Docker/反向代理提供示例，尚未运行验收；最终联合检查与干净制品按独立记录收尾，未据此宣布所有外部环境通过。返回[实施入口](../implementation.md)，阶段证据见[文档核对](../validation/documentation-audit.md#p8交付与验收)与[实施记录](../validation/progress.md)。

## 1. 测试与验证矩阵

| 层级 | 放置位置 | 必须证明的行为 |
| --- | --- | --- |
| 单元 | tests/unit/<模块> | 状态、边界值、代次、策略、数据转换；经导出接口验证 |
| HTTP 契约 | tests/contract/api | Schema、状态码、null/单位、鉴权、幂等、游标 |
| 插件契约 | tests/contract/plugins | 版本/能力、消息边界、取消、乱序、错误和数据通道 |
| 集成 | tests/integration | 真 SQLite、文件系统、worker/FFmpeg、HTTP 流、失败恢复 |
| Server 流程 | tests/e2e | 空目录启动到扫描/播放、重启、退出和交付配置 |
| 浏览器流程 | Web tests/e2e | 列表/点播/原生控件/处理流定位/错误与快速切歌 |
| 实机验收 | docs/validation 中的记录 | 有声输出、真实 codec、目标 OS、资源和体验限制 |

仅有 mock、通过编译、HTTP 200 或播放器 currentTime 增长均不足以证明可用音频。使用合法生成样本，在实际浏览器试听并校验输出片段、定位标记和已知波形；保留版本及输入摘要。

## 2. 逐步任务

### S-P8-01：可重复检查入口

1. scripts 提供 Windows/Unix 可执行的构建与测试入口或等价 CI job，所有路径从仓库根解析，不依赖个人绝对路径。
2. 执行 gofmt、go vet、普通测试、契约测试、真实集成测试和支持环境下的 race 检查；每项能分别判断失败/跳过。
3. 覆盖率使用 `go test -coverpkg=./src/... -coverprofile=build/coverage.out ./tests/...`，确认生产代码纳入统计。
4. 集成测试使用独立临时目录、动态端口、受控 worker/FFmpeg，不能连接开发者的生产库/音乐根。
5. 无网络的离线测试与需授权平台账号的探测分开；在线凭据放 CI 的受限机密管理，不提交到 fixture。
6. 文件长度检查作为拆分提示，超过 400 行需按职责评估；格式化/确实难以避免的例外有说明，不强制压缩可读性。

### S-P8-02：支持矩阵与性能基线

1. 首次记录 Windows amd64 和 Linux amd64 的 Go/SQLite/FFmpeg/插件版本；ARM64、其他 OS 只在实际通过后加入。
2. 对每个 browser/profile 记录输入格式、原流/处理路径、首帧、稳定播放、暂停、seek 精度、时间显示与已知限制。
3. 大目录、慢 NAS、长音频、VBR、并发播放、慢消费者和后台 hash/fingerprint 场景测量内存、CPU、队列、文件句柄、子进程和缓存增长。
4. 数值上限在目标机器原型测量后写配置默认与理由；不能在没有测量时承诺固定并发量或延迟。
5. 达到上限时排队/拒绝/降级行为可解释，后台任务不得饿死播放，取消后资源在有界期限回收。

### S-P8-03：构建制品和依赖

1. 为 Server 和每个官方插件分别构建可执行程序，附版本/协议能力、配置示例、文档入口和校验清单；Windows 使用正确后缀。
2. FFmpeg/ffprobe 根据实际构建来源和许可决定随包或显式外部依赖，记录安装方法、支持组件和版本检测行为。
3. 生成第三方参考/依赖清单，区分只用于设计参考与实际编译/分发；不能把 README 参考项目列成已经运行的组件。
4. Web 独立构建静态制品，Server 可经 `--web-root` 读取该制品或通过反向代理同源访问。构建复制的是制品，不将 Web 源码或嵌套 Git 仓库加入 Server。
5. 制品不含开发数据、音乐、token、私人路径、调试转储和测试账号。从干净目录按文档安装，而不是仅在开发工作区运行。

### S-P8-04：Docker 与本地运行说明

1. 本地给出配置、引导凭据、启动、扫描、打开 Web、停止和查看脱敏日志的完整步骤；命令以实际实现参数为准。
2. 容器使用受限用户，持久化 data/media/config，cache 单独控制；音乐默认只读挂载，标签写回需对指定路径显式配置可写。
3. SQLite 数据目录使用经验证的本地存储；音乐可来自已挂载 NAS，容器路径和宿主路径映射在示例中讲清楚。
4. 配置就绪/存活检查、停止宽限期、反向代理流超时和最大请求大小；代理不得缓冲整条长音频才发送。
5. 远程访问配置 TLS、可信代理头、明确来源和会话保护；浏览器 Cookie/CSRF 与 dev proxy 行为一起验收。

### S-P8-05：备份、恢复、迁移与回滚

1. 一致性备份包含 DB、被引用的 Media Store 文件、配置、插件版本和恢复清单；密钥材料按独立保护/恢复方案管理，不能只备密文却遗忘必需密钥。
2. 缓存可重建，人工歌词/封面、人工关联/隐藏和任务恢复日志不可当缓存丢弃。
3. 在另一干净 dataRoot 恢复，校验 schemaVersion、文件引用、凭据可用性和需要用户重新登录的状态。
4. 升级前检查协议/插件兼容、备份和迁移可用性；有数据结构变化时，不承诺任意旧二进制能直接读新库。
5. 回滚流程明确使用对应备份和制品，失败期间保持原音乐不被进一步写入；发布说明列出不可自动逆转的步骤。

### S-P8-06：Server 本地生命周期能力

1. 保存实例实际启动归属，独立启动默认不随客户端退出；随 Client 启动模式只在有鉴权租约协议时启用。
2. 服务端实现续租、正常释放、崩溃超时、首次无租约启动超时和 draining 拒绝新租约；新 Client 需重新发现。
3. 多个有效租约并存时不能由一个 Client 退出关闭服务；最后租约结束后有界收尾任务和文件写入。
4. 本轮只用协议测试客户端验证服务端行为，不把桌面进程锁、窗口、升级器等 Client 实现纳入本期。

### S-P8-07：发布前联合检查

1. 从零执行[跨端验收](../../../docs/implementation.md) E2E-01—08，至少完成 P3/P4 两个可播放节点。
2. 检查源文件前后摘要；默认扫描/刮削/播放不改原文件，只有已明确启用且通过能力验证的写回可修改。
3. 检查未支持输入、失效 Cookie、NAS 失挂、FFmpeg 崩溃、快速定位与 Server 重启的可见错误和恢复。
4. 对 README、架构、实施状态和实际制品做逐项核对；完成项附提交与验证记录，未完成项保留为待实现。
5. 平台参考清单更新到实际采用版本；对未知线上能力明确写未验证，不以第三方项目介绍代替本项目验证。
