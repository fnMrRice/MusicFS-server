## 2. 实现步骤

### S-P5-01：证据字段和失效模型

1. 为 SourceAsset 增加 bitrateMode/origin、providerSha512、fileSha512、hashStatus/computedAt 与算法证据版本；允许未知值，不修改稳定 SourceTrack 身份。
2. 区分原始申报、实际探测、估算与人工信息；保留 provenance，禁止把质量档位名称直接转成实测码率。
3. 证据绑定 asset/version/algorithm/config/range；更换资产时旧证据保留审计，但不再证明当前文件。
4. 旧任务发布使用预期资产版本和代次，文件变化后晚到结果不能写到新资产。

测试：VBR、未知码率、错误申报、旧任务、标签修改、不同音质同 SourceTrack。验收：API 与 DB 不混淆 null、0、待计算和不可获得。

### S-P5-02：后台完整文件 SHA-512

1. 用标准库流式读取和 SHA-512，低优先级、限并发、支持取消，不将整曲装入内存。
2. 通过 SourceAccess 获取同一稳定版本的完整读取；包括容器、标签和内嵌封面，不把 PCM 摘要填入 fileSha512。
3. 起止观测与稳定版本条件不满足时丢弃本轮结果。大小/mtime 校验只是变更线索，没有快照保证时不能给 verified。
4. verified 存 64 字节摘要，协议输出 128 个小写十六进制字符；部分 Range、重复片段或中途断开均不能发布完整摘要。
5. 与 Provider 申报值分开保存，冲突记录原因并撤销依赖错误申报值的自动证据。
6. 在线来源仅在授权、能力和完整读取条件允许时计算；不为匹配强制下载全部音乐。

测试：已知向量、空文件、不同分块、取消、读取中变化、大小相同内容不同、错申报、重复/缺片段。验收：同字节多路径可以识别，但不删除文件或合并其来源权限。

### S-P5-03：指纹提取和文件持久化

1. 选择并验证一个算法实现，例如 Chromaprint 候选，固定版本、依赖、提取配置和资源上限；此选择不自动授权外部检索服务。
2. 从用户 DSP 之前的解码音频提取；算法需要的重采样/声道规范化单独记录，不能使用用户 EQ 或变速后的输出。
3. 指纹明细保存为独立文件，DB 保存索引/摘要/覆盖范围/状态/证据引用。发布方式遵守临时文件→校验→文件发布→DB 引用切换。
4. 局部指纹明确起止范围；算法/资产变化重新计算，未知或不可得不阻止播放。
5. 默认仅本实例检索；要访问外部服务必须另有配置及用户授权范围，不自动上传私人指纹。

测试：同录音不同编码/码率、前导静音、不同现场/混音、局部采样、算法版本变化、提取取消与文件发布中断。验收：误匹配案例进入候选/待确认，不能仅相似即自动合并。

### S-P5-04：候选、人工确认和排除

1. 候选结合标签、版本标识、时长、已验证文件摘要与指纹证据，保存分数/依据/算法版本；分数不冒充概率或时间轴证明。
2. MatchExclusion 与人工决策优先，冲突/歧义候选留待确认；不以标题+歌手作为唯一键。
3. 人工关联、解除、拆分以预期修订提交并保留审计；来源条目和歌单出处不物理删除。
4. 提供管理 API/测试客户端完成候选选择，本期最小 Web 不因此增加复杂匹配页面。
5. 隐藏意图迁移接口提前留出原始目标和可逆记录，P7 歌单规则沿用，避免拆分后隐藏扩散。
6. 关联成功不自动生成 TimelineEvidence。时间轴验证独立提供方法、有效区间和版本，未实现时跨源恢复只能提示重播。

测试：排除优先、并发确认、错误合并解除、不同用户可见范围、同录音改标签、同名不同录音。验收：人工操作可追溯且可逆，候选不能泄露其他用户私有文件的存在。
