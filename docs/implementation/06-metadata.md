## 2. 实现步骤

### S-P6-01：建立文件对象和绑定

1. 定义 MediaObject 与 MediaBinding：对象类型、实际格式/MIME、大小、摘要、相对位置、来源/时间、适用目标/版本、人工状态、引用与修订。
2. mediaRoot 与音乐目录、普通缓存分离。歌词正文、翻译/时序、图片/缩略图和完整刮削文档存文件，不放 DB BLOB/Base64/正文 JSON。
3. 服务生成 objectId 和相对路径；上传文件名和远端 URL 不成为磁盘路径或永久 ID。
4. 限制输入大小、格式、解码资源和远程下载地址/重定向；扩展名不能代替内容类型检查。
5. GET /media/{objectId} 校验归属和引用权限，再交付文件；客户端拿不到 mediaRoot。
6. 歌词关联具体来源和时序适用范围，封面关联发行/来源专辑，Recording 合并不抹掉版本差异。

测试：中文/逐字歌词、多语言、非 LRC、错误 MIME、路径注入、损坏图片、越权读取及缺失文件。验收：DB 中没有内容正文，文件读取可按权限完成。

### S-P6-02：可恢复发布和回收

已落地并通过双平台验证，见[媒体恢复与备份](../media-storage.md)。完整配置/凭据/部署恢复入口在 P8 衔接。

1. 先建持久发布任务，再在目标文件系统 staging 写入并校验，安全发布不可变文件，最后事务切换引用。
2. 显式记录 prepared/written/published/referenced/finished 等恢复阶段；文件系统与 DB 不是一个原子事务。
3. 分别模拟写一半、重命名后未切引用、引用切换后未完成任务、回收过程中重启。
4. 失败保留旧引用，恢复按日志与文件校验决定继续或清理；禁止从“存在同名文件”直接推定完整。
5. 引用、活动任务、备份清单保护对象；过宽限期的临时/孤儿才回收，人工内容不作为可重建普通缓存淘汰。
6. 备份同时包含数据库、被引用文件和版本清单，恢复缺文件标可修复状态，不把人工内容当一定能重新抓取。

验收：每个崩溃点恢复后至少可读取上次有效发布内容，无仍被引用对象遭回收。

### S-P6-03：独立 Scraper 与手动流程

1. 注册 Scraper 独立角色/实例/凭据，首个官方插件提取本地内嵌或旁置内容；没有在线 Music Provider 也可工作。
2. 实现 scrape.search/fetch，将来源依据、语言、格式、可用字段和版本范围映射为候选；插件无权直接合并录音或写原音乐。
3. POST /metadata-jobs 接受单曲/来源专辑/批量目标、实例、字段与查询修正；任务返回逐目标状态与 candidateId。
4. 预览文件用受限对象引用，不能直接替换已发布选择。apply 校验目标修订和候选适用范围，再按字段发布。
5. 手动选用记录人工锁；晚完成自动任务不能覆盖。冲突以明确状态返回，不偷偷重试覆盖用户选择。
6. 取消保留已发布内容；批量可排除插件、重试失败项，每项结果独立报告。

测试：同一首多个候选、候选过期/目标变更、字段部分缺失、取消、插件停用、晚自动结果和批量部分失败。验收：手动过程和自动过程共用核心发布，不存在另一条绕过版本/权限的路径。

### S-P6-04：导入、编辑与自动补齐

1. POST /media 上传或保存编辑后的文件对象，PUT media-selection 以预期修订选择；上传/编辑不依赖第三方 Scraper 在线。
2. 自动策略明确触发点、实例优先级、字段和充分匹配条件，默认只补缺失且未人工锁定的内容。
3. 缺内容、失败或空候选不清空旧内容；人工解除锁定为独立动作，不由自动任务决定。
4. 去重下载/任务和缓存按用户、实例、目标版本隔离；凭据失效显示登录要求，暂停相关重试。
5. 手动触发、上传、选用都不自动开启 writeBack。

### S-P6-05：显式授权的原文件写回

1. writeBack.enabled 默认 false。按实例/根/字段控制，支持格式及安全替换能力由 Provider 明确报告；只读/NAS 不支持时拒绝写入而保留独立文件结果。
2. 写任务绑定预期 asset 和选定内容修订，检查活动播放/扫描/摘要，获得目标写入协调权；活动播放期间延后。
3. 默认补缺失，覆盖需明确配置；不清空缺字段，不丢未选/未知标签，不转码音频。
4. 在原文件同一文件系统准备临时副本与可恢复备份，校验结果及期望版本后安全替换；跨文件系统移动不能当原子写入。
5. 各阶段持久记录旧/新身份、备份、目标版本和写入结果，重启优先恢复；不能盲目重试覆盖用户外部新修改。
6. 成功后新建资产、重新探测/摘要，更新本地文件映射；确认仅修改标签时保持 SourceTrack、Recording、歌单、人工关联。
7. 原文件与 DB 更新之间的失败按恢复日志完成或回滚，不发布“写入成功但仍用旧 hash”的状态。

测试：默认不写、只读根、不支持标签、无安全替换 NAS、并发外部编辑、活动播放、磁盘满、每个崩溃点与成功后的稳定曲目身份。验收：默认前后原文件 SHA-512 不变；开启写回后成功有新摘要，失败有可执行恢复路径。
