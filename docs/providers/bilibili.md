# Bilibili 公开音频来源

网页端点和社区参考实现见[刮削与在线音乐源的接口来源](../plugins/provider-api-sources.md)。

插件 ID 为 `musicfs.plugin.source.bilibili`，安装包的 `release.json` 记录其独立版本。实现位于 `plugins/source/online/bilibili`，支持官方主进程装配、统一插件程序和独立 `musicfs-plugin-bilibili` 入口。当前仍在 Server 仓库维护，**尚未拆分独立仓库或发行**；风险与拆分建议见[可选插件发行](../plugins/optional-distribution.md)。

## 已实现的范围

- 匿名读取 BV、AV、标准视频链接与指定 `p` / `cid`，视频各分 P 使用独立 `video:<bvid>:<cid>` 身份。UP 主只作为上传者展示，不填成歌手。
- 音频区 `au` 曲目的元数据与来源详情；音频歌单 `am` 和视频收藏夹的元数据、完整分页观察、预览及远程歌单导入/同步。
- 视频收藏夹按平台顺序展开全部分 P，重复项保留；失效或非视频条目用不可播放占位保留顺序。分页失败、数量变化、私有化、限流和风控不发布空成功，也不替换已有快照。
- 元数据查询入口只解析准确 ID 或标准链接，**不支持关键词搜索、推荐或账号收藏夹发现**。短链、直播和番剧未接入。
- 公开内容的独立 AAC/M4A 音轨通过 Server 播放会话代理读取；平台 Cookie、签名 CDN URL 和请求头不返回浏览器。

本阶段不提供扫码登录、私有收藏夹、会员/付费内容、试听转完整音频、任意分 P 展开策略绑定、服务器网络音频转码。音频区与视频各自失败，不互相降级替代。

其他需要平台账号的在线插件尚不声明音频播放能力；后续开放前，还需绑定账号修订并在退出、切换或失效时撤销已有音频流。

## 按插件声明选择播放路径

来源插件握手必须声明 `sourceType: local` 或 `sourceType: network`，在线描述也包含此字段。声明缺失、无效或与角色不符时拒绝握手，来源类型不是用户配置项。来源插件的身份、网络访问和播放能力仍由宿主分别校验；声明网络来源不自动授予播放能力。

本地文件插件声明 `local`，复用现有文件读取、资源版本验证、快照和处理链。在线插件声明 `network`，宿主按类型选择按需读取流程，不根据 Bilibili 名称、扩展名或路径猜测。网络音轨先获取元数据和格式描述；`resolve` 建档及创建播放会话不请求音频正文、不完整下载、不做全文件哈希。只有已鉴权的播放器请求 `streamUrl` 时才打开上游音频。

首次按顺序读取音频，无需等待整段下载。缺少稳定字节版本时声明 `seekMode: none`，不发送固定字节 ETag，不允许非零 Range、If-Range 或重复消费同一 attempt；重播创建新会话。不能把元数据摘要、BV/cid 或 CDN URL 当作稳定音频版本。后续精确定位、网络转码和到期恢复需要扩展能力及独立验证。

平台返回受限或预览状态时明确失败；仅允许经过检查的 HTTPS API/CDN 目的地，连接时检查解析地址，逐跳校验重定向。当前无用户 Cookie，也不向 CDN 发送平台凭据。读取有大小、并发和取消边界。

## 使用入口

新配置默认发现 Bilibili；已有显式插件列表需添加对应插件。可参考 `configs/server.example.yaml`，每实例归属一个 MusicFS 用户，公开访问仍须登录 MusicFS。

1. 在 Web「设置 → 音乐来源」找到哔哩哔哩，打开链接查询，输入 BV/AV/au 或完整链接。
2. 在曲目结果右侧点击播放或加入队列，复用当前播放器。
3. 来源歌单页面粘贴公开收藏夹链接、`favorite:<编号>`、`am<编号>` 或音频歌单链接，先预览曲目。
4. 「歌单管理 → 导入远程歌单」支持相同输入。导入后自动同步曲目和来源并发布本地元数据快照，手动同步可更新快照。

收藏夹规范身份为 `favorite:<mediaId>`，音频歌单为 `audio-menu:<amId>`。相同数字不会跨类型合并。未完成的观察总数保持未知，不用已返回数量冒充完整总数。

## 验证与边界

2026-10-23，未注入平台 Cookie 的实际元数据请求成功：`BV13x41117TL` / `av8903802`、`BV1bK411W797?p=2`、`au1003142`、公开收藏夹 `1103407912`（当时为空）、`am10624`（当时 16 项）。公开视频与 `au` 播放地址/格式 JSON 也已返回；这些只证明当时接口可用，不证明作品的使用授权，也不代表所有平台内容可播放。

自动测试覆盖 ID/链接约束、分 P、两类集合分页、重复/失效项、部分失败、私有化、游标范围、用户隔离、平台错误、目的地与重定向约束。网络播放集成测试确认元数据建档、创建会话和 HEAD 不读取媒体正文；实际 GET 在上游尚未完成时传出首块，取消会关闭上游，完整缓冲结束后会话继续有效。浏览器测试通过匿名链接查询、加入队列、包含重复/失效项的集合预览，以及合成 WAV 的实际 HTML Audio 播放、时间前进和定位禁用。

同日对上述公开视频的实际 CDN 音轨读取 16,384 字节，确认 MP4 初始化标记后立即关闭，未完整下载。真实大型多页收藏夹、账号私有功能及真实音轨的浏览器完整播放尚未验收；首块读取不能替代整段播放验收。

协议设计的后续目标见[原设计](../design/bilibili-provider.md)；其中分 P 策略修订、完整 provenance、账号登录及恢复能力仍为待办。
