# 在线平台与 NCM 的可选发行建议

状态：2026-10-23 的工程与发行建议，尚未执行拆仓或改变默认发行方式。本文不作个案侵权认定；是否获得平台接入许可、作品使用授权及是否涉及受保护技术措施，需要结合具体用途判断。

## 当前实现与隔离程度

网易云、QQ 音乐及 Bilibili 属于在线来源适配；NCM 属于本地加密容器处理。前者主要涉及平台访问方式、账号范围及内容使用，后者还需要单独评估技术措施规避。插件的源码许可不能替代平台许可或音乐作品授权。

| 已有结构 | 实际边界 |
| --- | --- |
| 在线插件有独立 `go.mod`，平台实现共享适配代码 | 独立源码模块，仍由 Server 直接链接；不是独立发行隔离 |
| 构建提供 `-SplitPlugins` / `--split-plugins` | 额外生成平台程序；原 `musicfs` 和 `musicfs-plugins` 仍含对应实现 |
| 配置支持 `execution: process` 与 `enabled: false` | 控制运行方式及启停，不从安装包或主程序移除实现 |
| NCM 位于独立目录 | 解密核心、Worker 与宿主处理适配混在一个包内，仍依赖部分 `src/` 代码 |

具体事实入口：

- [主模块依赖](../../go.mod)、[在线插件模块](../../plugins/source/online/go.mod)、[在线宿主](../../src/plugins/pluginhost/online_process.go)和[统一程序入口](../../plugins/unified/select.go)。
- [默认插件装配](../../src/core/config/bundle.go)、[构建脚本](../../scripts/build.ps1)和[发行程序清单](../../scripts/release/programs.go)。
- [NCM 宿主适配](../../plugins/decoder/ncm/processor.go)、[启动装配](../../src/app/bootstrap/plugins.go)、[解码链](../../src/plugins/audiocodecs/chain.go)和[格式注册](../../src/plugins/audiocodecs/formats.go)。
- 现有 [Server SDK 约定](plugin-sdk.md)与[总体架构](../../../docs/architecture.md)要求官方内置实现运行于主进程；可选外部发行需要同步明确新的分类，不能把进程隔离等同于权限沙箱。

## 建议的目标结构

建议先采用“核心 Server + 在线可选插件仓库 + NCM 独立仓库”，而不是为每个平台立即建立一套重复基础设施。在线仓库可以保留共享适配层，但网易云、QQ 音乐、Bilibili 分别构建、版本化和发行；后续确有维护或授权差异时再拆成独立平台仓库。

核心发行只包含通用宿主、SDK 协议、本地来源及已选定的基础处理实现，不默认编译、打包或自动下载上述可选插件。用户安装明确选定的插件并配置可信程序及摘要后才启用。NCM 不混入在线插件包，保持独立的发布评估与停止发行能力。

这能减少核心安装包直接携带相关实现的范围，便于分别维护、替换和停止发行；仓库位置、开关、进程边界或免责声明本身均不能免除开发、提供或使用相应功能的责任。

## 可实施的拆分顺序

1. **建立真实构建边界。** 将在线实现移至独立仓库，使用 `git mv` 保留仓库内移动记录；保留只依赖 SDK 的方向。移除核心对在线实现的直接导入，不能仅删除默认配置。若仍需同进程扩展版，应使用显式构建选择并单独发行；当前不支持安装任意动态库后自动加载。
2. **拆开 NCM 实现与宿主适配。** Worker、解析和解密实现进入独立插件模块；宿主保留通用协议客户端、生命周期、授权读取和发布协调。去掉 NCM 对 `src/core/logging`、`src/plugins/pluginconfig`、`src/plugins/plugincontrol` 的反向依赖，通过 SDK 契约及插件自述承载必要信息。
3. **去掉默认携带与自动装配。** 同步调整 `musicfs`、`musicfs-plugins`、容器、发行清单、示例配置与默认发现。仅将实现从主程序移到随包工具，或者保留禁用的静态实现，均不满足目标。
4. **固定可验证制品。** 每个平台使用独立版本、目标平台、摘要、协议版本和依赖许可清单；核心与可选包分别验收。测试应验证核心构建依赖图及安装包确实不含实现，并覆盖插件缺失、摘要不符、启动失败与已有曲库可访问性。
5. **同步文档与版本管理。** 更新总体架构、插件边界图、配置及发布说明。沿用项目现有的私有发行约定，不因拆分自动公开仓库或制品；创建远端仓库、迁移历史、公开发布与更换许可证需有明确任务范围。

## 权利与使用范围

在线适配应明确支持公开内容或已取得授权的账号范围。能在官方客户端播放、已购买会员或用户自行提供账号，并不当然意味着已获第三方接入、复制、下载或向他人传播的许可。元数据查询也可能受平台服务条款约束，但违反平台条款与侵犯作品著作权是不同判断，不应混为一谈。

NCM 的现有功能包含本地加密音频提取，见 [NCM 说明](../playback/ncm.md)及[实现参考](../../plugins/decoder/ncm/REFERENCES.md)。参考 MIT 实现、独立重写、文件来自本地或声明仅供学习，都不能单独证明相关使用或发行合法。第 49 条关于技术措施的规则与第 50 条的有限例外需要单独评估；不能将一般个人使用推定为允许对外提供解密工具的例外。

仓库的 [GPLv3 许可证](../../LICENSE)及第三方代码许可处理的是软件代码权利，不授予歌曲、录音、封面、歌词或平台服务权利。拆分时应保留适用许可和版权通知，不把独立目录误写成已取得独立许可。
