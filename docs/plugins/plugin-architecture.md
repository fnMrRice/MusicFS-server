# Server 插件架构

Server 保持 Go 模块化单体，来源适配、内容提取和音频处理由受管 Worker 执行；核心负责权限、状态、事务发布和生命周期。共同边界见[总体架构](../../../docs/architecture.md)与[跨端插件边界](../../../docs/plugin-boundaries.md)。

## 当前能力

默认交付 `musicfs` 与 `musicfs-plugins` 两个程序。统一插件程序通过 `--plugin` 选择九种用途，每个实例或任务独立启动进程；它不是让九种插件共享一个运行上下文。源码分为 Server、SDK、在线插件三个 Go 模块，见[SDK 与构建](plugin-sdk.md)。

| 用途 | 当前职责 | 协议与限制 |
| --- | --- | --- |
| `local` | 本地文件及已挂载 NAS 的观测、元数据、受限资源解析 | 通用 `provider`；根授权、稳定身份、扫描发布由宿主执行 |
| `netease`、`qqmusic`、`applemusic` | 各平台账号控制及已声明的资料能力 | 通用 `provider`；业务要求已校验账号，真实账号验收与能力范围见[平台登录](../providers/platform-login.md) |
| `scraper-local` | 本地内嵌及旁置歌词、封面候选 | 通用 `scraper`；不选用内容、不写原件，正文走任务二进制通道 |
| `audio-ffmpeg` | 探测、解码、编码、规范化及有序 DSP 链 | 通用 `audio`；固定任务和受控输入/输出，见[音频处理](../playback/audio-processing.md) |
| `ncm` | 解密 NCM 外层容器，保留 MP3/FLAC 编码字节 | 通用 `audio`；源资产与解密表示分离，见[NCM](../playback/ncm.md) |
| `dsp-gain` | 无状态、保持帧数和时标的 PCM 增益 | [DSP v1](dsp-plugins.md) 专用协议；零延迟、无尾音 |
| `storage-sqlite` | 可信后端的原子业务操作、实例状态与快照 | [持久化专用协议](storage-plugins.md)；SQLite 必需，不能停用 |

九种命令行选择值与通用 Manifest 的 `provider/scraper/audio` 三种角色是不同层次。DSP 和存储不向通用 Manifest 添加角色，也不使用普通实例启停接口。它们在管理列表只读展示启动配置及状态，修改部署配置后重启生效。

普通插件按官方固定身份与角色适配器接入；未知 ID、角色、方法及超出平台策略的能力被拒绝。插件声明可以收窄已支持能力，不能授予额外权限。当前没有任意第三方自动发现、下载、安装、升级回滚或管理 CLI。

## 宿主与插件的职责

| 插件可以提供 | Server 必须校验和提交 |
| --- | --- |
| 平台登录交互、账号状态及上游资料 | 用户/实例归属、凭据范围、业务登录门槛及账号撤销 |
| 文件观测、基础标签和资源版本证据 | 授权根、SourceTrack/SourceAsset 身份、扫描完整性及缺失复核 |
| 指纹、候选分数或媒体变换结果 | 输入版本、证据有效性、人工禁止关联、时间轴证据和任务预算 |
| 歌单分页、推荐顺序 | 完整快照、出处、隐藏意图、幂等和事务；失败不发布成功空列表 |
| 受控音频输出 | 来源选择、依赖租约、attempt/表示版本、Range、定位及恢复预算 |
| 歌词/封面候选及正文 | 类型/尺寸/摘要、预览、人工锁、内容发布、原件安全写回 |
| 可信后端的原子操作与快照 | Schema/迁移版本、业务事务、实例隔离、文件保护协调和恢复判断 |

`host.state.*` 与 `host.database.*` 只提供实例隔离的受限状态，不提供任意 SQL 或核心数据库权限。所有结果先检查大小、类型、归属、输入版本、运行代次和目标修订，再进入核心发布流程。

## 协议、安全与生命周期

- 通用控制面使用 JSON-RPC 2.0 / stdio、`Content-Length` 帧、UTF-8、1 MiB 消息上限和 `h-` / `w-` 请求 ID。stdout 仅用于协议，英文诊断写 stderr；精确字段以[协议说明](../contracts/plugins/v1/README.md)与 Schema 为准。
- `host.hello` 校验实例、nonce、配置修订、角色、发行版本及协议；握手前不接业务。`$/cancelRequest` 统一取消，晚结果只能回收，不能发布。
- 音频、NCM 与 Scraper 使用各自的任务限定二进制通道，不把正文放进控制 JSON。网络声明不能替代文件根、平台目标或 NAS 地址授权。
- 管理停用只保存配置，当前 Worker、任务、播放和新工作准入保持，重启 Server 后生效。启用与实例设置可动态应用；设置重建关闭目标实例准入并等待旧租约，详见[插件管理](plugin-management.md)。
- 进程隔离、摘要核验和受控 Broker 不构成 OS 沙箱。当前只运行管理员信任的程序；插件仍拥有服务账户的系统权限。

升级统一文件须先正常停服，保留旧制品及状态快照，更新固定摘要后重新握手；不能覆盖运行中的程序。状态不兼容时拒绝继续启动，不能让旧 Worker 写入新格式。安装与回滚的自动化入口仍未实现。

## 待扩展范围

以下是设计边界，不是可直接加入当前配置的功能。

| 扩展 | 前置条件 |
| --- | --- |
| 原生 NFS/SMB、Bilibili 与在线整曲 | 远端资源模型、目标授权、稳定字节版本和受控读取；见[NAS / Bilibili 计划](../design/nas-bilibili.md) |
| 有状态 DSP、重采样、任意音频图 | 明确延迟、尾音、预滚、格式变化、定位与失败策略；现有 DSP v1 不覆盖 |
| 可替换分析、内容变换、标签及策略插件 | 先定义最小结果契约、权限、版本、取消和资源上限；录音关联、内容选用与事务仍由核心负责 |
| C++ Worker / SDK | 真实 Go Host 互通、严格 DTO、二进制通道、取消及目标平台制品验证 |
| 第三方安装与更新 | 独立身份注册、制品信任、配置迁移、恢复与额外系统隔离验证 |

新增扩展先判断能否复用既有角色，再同步协议/Schema、宿主注册与校验、Worker、配置迁移和测试夹具。影响公开能力或状态时同步评估 OpenAPI、事件及 Client/Web。使用新旧 Worker 验证接受和拒绝边界后再发布配套制品；协议、插件、算法、配置及资产版本不能互相替代。

需要 C++ 的实现统一使用 [CMake / C++23](../../../docs/native-plugins.md)，交付独立 Worker，不让 Go Host 加载 C++ 类或 DLL。Client 的原生插件在同一原生宿主进程加载动态库，与 Server 分别适配、构建、发布和验收；可共享算法源码和测试向量，不承诺共用二进制。当前尚无已验证的 C++ Worker 或通用 C++ SDK。
