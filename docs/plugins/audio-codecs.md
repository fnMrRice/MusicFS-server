# 音频编解码插件

音频格式识别和解码选择使用 `sdk/audioformat`。插件声明自己的文件头探测、候选扩展名及识别优先级；宿主每一层按优先级从高到低轮询，相同时保持注册顺序。扩展名只用于寻找待扫描文件，不能证明内容格式。探测输入最多读取 4096 字节，宿主不再判断 NCM 文件头。

扫描先按插件声明的扩展名筛选，再探测实际内容。改名为 `.wav` 或 `.mp3` 的 NCM 仍可正确识别；未知扩展名、`.backup` 备份和临时副本不会被扫描成额外来源。直接调用 SDK 的内容探测不依赖文件名或路径。

`Decoder` 将 `Detector` 和 `Decode` 组合。输入包含受授权的 `io.ReaderAt`、真实长度、通用格式描述与元数据。解码请求包含任务和资产身份、希望取得的输出格式、输出字节预算；返回值除新的输入描述外，还明确声明 `NeedsDecoding`。返回 `true` 时宿主重新识别输出并选择下一层，返回 `false` 时结束解码。只有显式 `ErrUnsupported` 才尝试下一匹配插件；源文件变化、损坏、权限或实例不可用等错误立即停止。宿主限制最多 8 层，并拒绝重复输入形成的循环。

NCM 插件优先识别加密封装，输出内部原始 MP3 或 FLAC，保留元数据并声明还需后续解码。FFmpeg 插件识别普通音频表示；输出为 `native` 时保留原表示并明确结束链，因此原生播放和元数据读取不必先生成大体积 PCM，也不需要启动 FFmpeg 工具。要求 `pcm_f32le` 或 `pcm_s16le` 时，则实际调用已验证工具，生成保留源声道布局的 48000 Hz WAV，并标记解码结束。每层只能关闭自己创建的资源，最终结果关闭时按相反顺序回收所有中间层。

FFmpeg 插件另有显式 `Processor.Transcode` 能力，支持工具实际声明的 MP3、FLAC、Opus/WebM、WAV。MP3 与 Opus 使用固定 48000 Hz 双声道、128 kbps；FLAC 保持可表示的源参数，WAV 使用 16 位整数 PCM。转码需要明确调用，不自动重新进入解码循环，也不执行用户播放 DSP。该能力目前为插件/宿主接口，没有向 Web 增加导出文件入口。

PCM 和转码结果仅写入受限任务临时文件，不写回来源。默认输出预算 256 MiB，调用方可收紧，上限 1 GiB；播放额外把临时结果和独立播放副本同时计入缓存预算。关闭、取消、工具错误或超限都回收输出；输出可用期间保留插件生命周期租约，避免任务完成就失效。

`Decoded.Close()` 按逆序关闭中间层；成功关闭的层不重复执行，失败的层可以再次关闭重试。清理失败包含 `audioformat.ErrCleanup`，宿主须保留对应额度并安排恢复清理，不能因逻辑任务已结束就把未删除文件视为空闲空间。

FFmpeg 的声明式设置页面可为当前用户选择 `native`（默认）、32 位浮点 PCM 或 16 位整数 PCM，在新播放会话生效。NCM 页面只声明它真正支持的“保留原始 MP3/FLAC”。用户偏好不会改变音频指纹的固定单声道 11025 Hz、s16le 规范。活动会话保留创建时的选择；16 位与浮点解码在处理缓存和跨来源时间轴证据中使用不同身份，不能复用不适用的结果。

FFmpeg 与 NCM 在管理界面属于“音频编解码”；声道转换属于 DSP。声道插件默认禁用，布局在 Web 本地选择；服务端仅保留必要格式适配。显式启用的声道插件在解码之后、效果链之前运行，不替代文件格式探测。显式外部 FFmpeg Worker 必须与 0.7.0 宿主插件实现配套，旧 Worker 在任务执行前拒绝。

当前由受信任组装层注册官方编译内探测声明，既有外部 Worker 继续执行经过身份、摘要和资源授权检查的解码任务。通用 SDK 接口不代表已经交付任意第三方动态安装或格式探测 RPC；新增探测插件仍需通过受信任组装接入。
