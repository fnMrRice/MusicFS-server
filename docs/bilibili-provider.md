# Bilibili 音频 Provider 设计

状态：2026-10-10，设计与实施计划，尚未实现或进行 B 站在线验收。插件拟为 `musicfs.bilibili`；任务见[增量实施计划](implementation/nas-bilibili.md)，开源依据见[参考记录](provider-references.md)。以下身份格式与能力划分为草案，精确协议由 Server 后续冻结。

## 1. 匿名优先与能力边界

以公开内容的免登录读取和播放为基础目标，不能将登录设为启用插件、粘贴公开链接或播放公开音轨的前置条件。无需 B 站账号不等于无需 MusicFS 登录，来源与播放会话仍受 Server 授权。匿名设备标识、签名参数与账号凭据分开管理；接口需要匿名 Cookie 不代表需要用户登录。

用户主要通过视频收藏夹组织音乐；收藏夹是第一优先的远程歌单来源。同时纳入音频区 `au` 曲目和 `am` 独立歌单，分别探测和验证能力。不能因视频音轨成功就宣称音频区可用，也不能因音频区失效而阻塞收藏夹播放。

| 内容 | 目标接入 | 能力与失败边界 |
| --- | --- | --- |
| 公开视频 / 分 P | 指定 BV/AV 或规范链接，获取分 P 列表与纯音频轨 | 匿名优先；每 P 独立身份、时长与播放尝试 |
| 公开收藏夹 | 输入收藏夹 ID/链接，读取资料与有序条目，导入或绑定同步 | 按来源标记“收藏夹”；读取公开指定收藏夹不要求先登录 |
| 音频区曲目 | `au` ID/链接读取资料和音频 | 独立验收，未知字段保留 null |
| 音频区歌单 | `am` ID/链接读取资料和全部分页曲目 | 按来源标记“音频歌单”；不与收藏夹 ID 混用 |
| 私有收藏夹 / 受限内容 | 可选 B 站账号授权 | 权限、会员、地区及内容状态逐项判定；登录不保证可播放 |
| 搜索 / 推荐 / 本人收藏夹发现 | 后续按端点验证 | 首批可从指定链接导入，不假装所有查询能力已支持 |

上游明确要求账号时返回 `AUTH_REQUIRED`，已授权但无权限用 `ACCESS_DENIED`；风控、限流、网络故障与失效内容分别呈现。不能把所有匿名失败都解释为需要登录，也不静默借用其他用户账号。账号授权作为后续增量沿用[平台账号机制](platform-login.md)，扫码方式待实测；手工 Cookie 仅作诊断不能冒充已交付登录交互。

## 2. 曲目、收藏夹与音频歌单

| 对象 | 拟用来源身份 | 约束 |
| --- | --- | --- |
| 视频音轨 | `video:<bvid>:<cid>`，再与实例组合 | AV 规范到 BV；P 序号只作展示，cid 变化不能覆盖旧曲目 |
| 音频区曲目 | `audio:<auId>` | 与视频命名空间分离，即使标题相同也不自动合并 |
| 收藏夹 | `favorite:<mediaId>` | 保留收藏夹所有者、可见范围和规范来源页 |
| 音频歌单 | `audio-menu:<amId>` | 映射 RemotePlaylist，不因参考工具名为 Album 就强行映射发行专辑 |

收藏夹与音频歌单统一进入已有 RemotePlaylist → 本地快照 → 聚合歌单流程。只是预览时不入库；导入为一次本地副本，绑定才开启后续同步。所有操作默认只读 B 站，不向收藏夹/音频歌单写回。

收藏夹视频默认按上游条目顺序、视频内 P 顺序展开全部分 P；导入预览显示展开后的曲目数，允许用户改成仅 P1 或选定分 P。展开策略保存到 binding 修订，变更后重新预览与发布；音频歌单按上游曲目顺序，无分 P 展开。保留收藏夹条目、原视频、cid、原位置与展开策略的 provenance，重复出现不丢失。

来源条目有稳定 ID 时优先使用；没有时保存 Host 对账身份与原始对象、出现次数证据，不能把 position 当持久 ID。失效视频、缺失分 P 或未知资源类型保留不可用占位及原因，不静默跳过导致列表缩短。UP 主是上传者，不能未经证据直接当演唱者；视频/收藏夹名也不直接视为音乐发行专辑。

两种集合都要完整翻页并设总条数、页数与耗时上限；超限、风控、部分失败返回 incomplete/truncated，保留旧快照。无远端一致修订时声明 `unversioned`，翻页成功不证明集合未变化；缺失项经再次完整观察或独立核查才撤去贡献。公开变私有或账号失效不能当作空歌单发布，私有快照与缓存按用户/实例/账号隔离。

## 3. 音频解析与交付

优先选择平台返回且当前权限允许的独立音轨，不下载视频再默认转 MP3。保留音质标识、codec/container、时长、码率来源；AAC、FLAC 等只在实测通过后声明。只有混合流、分段旧格式或无法保证完整内容时，首批明确不支持或标为预览，不能将试听片段标为整曲。

参考 yt-dlp 的 Bilibili 提取器，优先用 Go 在独立 Worker 内适配已核验的端点与签名流程。客户端接口优先策略按端点评估；公开视频可先采用经验证的 Web 请求方式并记录理由，不为匿名播放强加账号登录。外部 yt-dlp 仅为备选解析路径，采用前须固定版本、限定提取器、关闭隐式配置/插件/自动更新、限制子进程并验证 URL 与请求头，不作为本轮新增运行依赖。

短期 CDN 地址与必要 Referer/请求头仅保存在受控服务端资源中，音频由 Server 鉴权代理或处理。校验 HTTPS、允许域名、DNS 地址和每跳重定向；签名 URL、Cookie 不出现在普通 DTO、日志或浏览器。凭据只发给明确允许的认证目标，不能把平台 Cookie 无差别转发到 CDN。

`metadataDigest`、BV/cid、音质编号与 URL 都不单独证明固定字节版本。resolve 需提供可核验的版本证据；CDN URL 更新不自动创建内容新版本，也不能据 cid 相同沿用旧 Range。无法证明字节稳定时禁用跨请求字节续接，并按实际能力选择 `timeRestart` 或 `none`。过期恢复使用已有有界预算，新尝试返回新 representation；无法证明时间轴兼容时提示重播。

现有在线 resolve 返回 `UNSUPPORTED`，未创建音频资产；因此必须补齐在线来源建档、SourceAsset、受控网络资源、会话与处理链输入，不能只把解析 URL 接入资料接口。也不能将远程 URL 填进 `relativePath`。复用共同播放会话与音频处理，不增加 B 站专用浏览器播放器；封面/歌词选用仍遵循独立 Scraper 边界。

## 4. 验收场景

- 全新匿名实例、不预置用户 Cookie：公开单 P、多 P 音频播放及定位；公开收藏夹从链接预览、导入、同步，真实浏览器验证音频内容。
- 音频区 `au` 与 `am` 单独实测，歌单超过一页、空集合、重复项、失效项和部分失败；不可用时只禁用相应能力，不伪造支持。
- 收藏夹多 P 展开、选定 P、P 重排/替换、集合变私有、翻页期间变化、撤销贡献与 provenance 保留。
- CDN 过期、重新解析、输入版本变化、无 Range、预览限制、取消和限流；无无限重试、完整预下载前置或旧偏移拼接。
- 私有功能另验账号授权/退出/过期、跨用户隔离和缓存清理；不得用匿名样本替代私有收藏夹验收。
