# NFS / SMB NAS Provider 设计

尚未实现或进行 NAS 实机验收。总体语义见[跨端架构](../../../docs/architecture.md)，任务和候选依赖见[增量计划](nas-bilibili.md)。本文字段为设计草案，不是可用的 YAML / SDK。

## 1. 接入方式与首批范围

拟新增 `musicfs.plugin.source.smb`、`musicfs.plugin.source.nfs` 两个独立 Music Provider，直接连接 NAS。各自配置、启停、声明能力和保存实例凭据。已挂载 NAS 继续由 Local Files 使用，三种接入方式不自动迁移或按同名合并来源。

| 插件 | 首批目标，均待验证 | 后续评估 |
| --- | --- | --- |
| SMB | SMB 2/3、指定主机和共享、账号认证、只读枚举及音频读取 | Kerberos、DFS、变更通知等分别验证；不支持 SMB1 |
| NFS | NFSv3/TCP、指定 export、显式 UID/GID 与 AUTH_SYS 配置 | NFSv4、Kerberos、变更通知分别立项；不能从 v3 验收推断支持 |

首批目标能力为 `library.scan`、`metadata.read`、`stream.resolve`；NAS 文件标签探测仍复用 Server 音频链。账号认证属于 NAS 连接配置，不映射为音乐平台扫码登录。默认无写回、删除、远程歌单或推荐能力；远端旁置歌词/封面读取需另验证受限目录访问，不能因 Local Scraper 已存在就宣称支持。

## 2. 配置、授权与生命周期

| 草案配置项 | 约束 |
| --- | --- |
| 公共 | 实例、主机、协议版本、超时、并发、扫描深度/排除规则、期望共享身份 |
| SMB | 端口、共享名、共享内子目录、域/用户名、Host 托管的 `credentialRef`、签名/加密要求 |
| NFS | export、子目录、UID/GID/附加组、RPC/mountd/NFS 端口策略；默认不使用特权源端口 |
| 授权根 | 管理员显式允许的远端根；普通用户只选择自己可见实例，不提交任意服务器地址 |

SMB 密码不进入普通配置导出、manifest、命令行或日志。NFS AUTH_SYS 身份由管理员固定，UID/GID 不是密码认证，不能由普通请求切换。NAS 可以位于私网；为此使用独立于在线公网 Provider 的目标白名单，并对 DNS 变化、RPC 返回端口及重连重新校验。不得将“允许一个 NAS”扩大为任意内网代理。

连接、树/导出、文件句柄按实例与运行代次持有；读请求有超时、取消和背压。停用仅保存开关，当前连接、任务和新工作准入保持，重启 Server 后生效；配置重建及正常退出按租约收尾并关闭连接和数据通道，旧进程结果不能发布到新代次。认证失败、权限拒绝、断线、句柄失效和文件变化分别返回稳定错误，不输出上游秘密。

## 3. 扫描、来源身份与资产版本

沿用扫描代次、授权范围、页大小上限、取消和发布修订。扫描页保留根身份、完整性、游标及问题；子目录权限不足、枚举中断或游标失效均为不完整扫描。断线不返回空的成功库，不删除历史曲目、歌单贡献或人工关联。恢复后重新完整核对，缺失条目仅更新可用性。

Host 为来源分配持久 externalId，并保存远端根身份、相对路径、协议文件标识和观测证据。SMB 文件标识与 NFS 文件句柄/文件系统标识仅在验证的服务器与生命周期范围内使用；不能假定跨 NAS 重启永久稳定。重命名只有在身份可靠时保留 SourceTrack，复制保留独立来源；无法区分替换与移动时保留歧义，不能用路径或大小/mtime 猜测相同文件。

协议文件属性用于发现变化，不自动构成强字节版本。打开前后和读取期间校验身份及可得的变更证据；原地覆盖、同大小修改、重连句柄变化必须被测试。无法保证固定版本时，不宣告稳定 Range / verified SHA-512；可评估受配额约束的完整快照，但必须确认快照读取的一致性，不能把读中混合内容标为可靠资产。

绑定的共享/export 身份改变时暂停扫描并要求重新确认根绑定；新配置不能借旧根 ID 复用旧资产。符号链接、junction、DFS referral 默认不跟随，后续若支持须再次校验实际目标属于授权范围。大小写、Unicode、超长路径、链接循环与目录深度都有明确边界。

## 4. 受控读取与播放

现有 `sourceaccess` 依赖 `os.Root` / `os.File`，`pluginproto.Resource` 仍按本地根与路径描述。原生 NAS 不能仅更换插件名称后复用这些实现。需先扩展远端资源描述及可取消读取能力，以不透明资源引用连接 Worker 和 Host；本地适配保留既有语义，远端引用不能被解释为磁盘路径。

控制面沿用版本化 JSON-RPC/stdio，只传资源、版本与任务信息；音频正文走 Host 授权的独立二进制通道。资源绑定用户、实例、任务、资产版本、允许范围及有效期。Web/Client 只读 Server 播放地址，不直接访问 NAS 或获得 NAS 凭据。

只在同一固定表示可以随机读取时提供 `byteRange`；每次 seek/重连都须复核版本。原流经 Server 代理，兼容处理、DSP 或 NCM 解密复用既有插件链，但需验证它们能消费新资源。处理后偏移不能沿用源文件偏移；输入变化返回 `RESOURCE_CHANGED`，恢复产生新 attempt，不能在旧响应中拼接新文件。

## 5. 完成门槛

- 两种协议分别完成扫描、入库、重启恢复、原流、定位和处理后播放；真实 NAS 与模拟故障结果分开记录。
- 验证断线/重连、部分权限、共享替换、同大小覆盖、文件重命名/复制、过期句柄、取消和慢消费者；无误清库、跨版本续流或无限等待。
- 验证跨用户/实例/任务引用、路径越界、链接和目标重定向、凭据脱敏、保存停用后继续工作及重启后停用；其他来源保持可用。
- Windows / Linux Server 分别记录 NAS 服务端版本、协商协议与安全选项；通过项才写入支持矩阵，不扩大为所有 NAS 兼容。
