# 在线资料刮削插件

各插件的数据来源、实际请求和上游文档见[刮削与在线音乐源的接口来源](../plugins/provider-api-sources.md)。

在线资料搜索失败后，由用户手动再次搜索。平台返回 HTTP 错误时，可通过响应中的 `error.scraper.pluginId`、`reason` 和 `upstreamStatus` 核对来源和状态码。`upstream` 表示本次访问收到了平台响应，`cooldown` 表示前一次平台响应要求的等待时间尚未结束，本次搜索会直接返回。`busy` 表示 MusicFS 的并发搜索已满。平台给出有效等待时间时，响应会带上 `Retry-After` 和 `error.retryAfter`（秒）。页面上的请求编号可用于在服务日志内找到对应原因。

打开作品详情中的「搜索在线资料」，或从曲目入口搜索歌词、封面。选择内容和来源，核对候选的版本、来源页面及预览后选用。作品资料按字段保存，并保留来源编号；后续编辑作品标题或简介会保留已选曲目表和图像。选用来源曲目的歌词或封面会发布到媒体对象库，并通过现有媒体修订与人工锁生效。

「曲目列表 → 专辑」打开具体专辑后，点击专辑名右侧的「详情」可查看已保存资料和平台页面。在详情中点击「刷新资料」左侧的「搜索」，可查询专辑详情、完整曲目表和封面。先选择发行版，再以同一来源编号读取全部曲目，预览后一并保存；上游未返回完整曲目时不发布半份资料。MusicBrainz、iTunes、Bangumi、网易云音乐和 QQ 音乐都支持填写相应的 HTTPS 专辑页面。插件从页面地址提取发行版编号，再向平台目录查询。「未知专辑」没有独立专辑身份，不提供此入口。

选用结果按当前音乐专辑和字段保存，并在同一事务补齐专辑曲目：优先复用专辑内唯一精确匹配的已有曲目，缺少音源的曲目建为资料条目，以灰色显示；按平台碟序和曲序排列。相同发行版重刮按位置复用身份，保留人工编辑及真实来源，不重复建档。原来额外关联的曲目继续保留，排在平台曲目之后。「全部曲目」仍使用有来源过滤。保存校验专辑修订并支持幂等重试，刷新、重启后仍可读取。

首次读取平台专辑详情和曲目表后，再次预览同一发行版时优先使用缓存。要核对平台的最新资料，可在预览中点击「刷新预览」，或从已关联专辑的「刷新资料」入口重新读取。刷新成功后展示新资料，写入曲库仍需确认选用或合并。

专辑封面读取优先采用已选封面、专辑详情图像，再回退专辑原封面、普通曲目和当前可见来源封面。返回受鉴权媒体地址或有效 HTTPS 图片地址，不把文件系统路径当作网页图片。专辑名可用原有编辑接口手动修改；只读的 `originalName` 始终保留首次名称。

曲目和歌手可分别保存多种语言的名称。曲目接口使用 `localizedTitles`，歌手使用 `localizedNames`。每项包含 BCP 47 语言标签 `language` 和名称 `title`，同一语言可有多个别名。使用曲目名称或已保存的别名均可查询。在线资料中的主名和别名可在曲目主行的「更多 → 搜索在线资料」中确认，歌词和封面按所选来源版本保存。

在同一专辑中勾选曲目并指定保留的主曲目后，`POST /api/v1/library/albums/{id}/merge-tracks` 一次提交选中的有来源及无来源曲目。请求带专辑修订、录音关联修订、每首曲目修订及幂等键。多个独立来源合为同一录音时，结果可以取得新的录音编号，调用方按响应中的 `trackId` 读取结果。当前专辑的手工合并在同一发行版重刮时生效。如果这些歌曲同时占用了另一张专辑的不同平台曲位，服务端返回 `ALBUM_TRACK_SLOT_CONFLICT`，用户可先核对另一张专辑。

iTunes 刮削以所选商店的名称为主。查找日文作品时，在「更多查询条件 → 查询地区」填写 `JP`，或粘贴带 `/jp/` 的 Apple Music 专辑页面。日本商店的搜索和读取均显式请求日语（`lang=ja_jp`）。日区专辑候选按编号批量补查歌曲行，优先使用同一发行版歌曲行中一致的专辑名。补查失败、缺少名称或名称冲突时，保留原有专辑候选。具体写法取决于 Apple 收录的资料。留空地区时默认美国商店；使用专辑页面时，以链接中的地区为准。

插件会向日本、美国和台湾商店批量查询曲目及歌手的其他写法。同一首歌须同时匹配 Apple 曲目编号和专辑编号。曲名和完整艺人署名都参与专辑曲目匹配，合作曲按完整署名核对。独立歌手资料按 Apple 艺人编号取得别名。商店没有返回语言标签时，其他名称以 `und` 保存，可在曲库里再指定语言。地区无授权、补充查询失败或超时，仍可选用所选商店的资料。Bangumi 的中文章节名使用 `zh`，MusicBrainz 的别名保留其提供的语言标签。

Bangumi 的音乐章节可以把艺人署名写在曲名里。插件会将能够识别的署名单独放入艺人栏，将本曲明确标注的作曲者放入作曲栏。同名曲的不同演唱版本各占一个曲序。此前已保存的专辑可从「刷新资料」选择 Bangumi，读取后勾选「曲目表」并合并。服务端按章节编号更新可确认的旧刮削占位曲目，已编辑的显示名和本地音源资料会保留。

专辑可以同时关联多个平台。在专辑详情中点击「搜索」，每次选择一个资料平台。切换平台可继续查找其他来源，点击「编辑资料」可新增、修改或移除各平台的页面。专辑的 `sourceLinks` 为 `{pluginId,url}` 数组，每个平台可以保存一个无凭据的 HTTPS 页面。旧版保存的链接在升级时迁入。选用新来源的资料也会关联其页面。单独保存链接后，可在「刷新资料」中选择平台，再读取完整详情和曲目表，比较后勾选要合并的字段。

对比合并支持名称、歌手、发行日期、发行商、音乐风格、说明、封面和曲目表。只发布明确勾选的字段，未选的已保存详情也保持；部分日期保留年份／年月精度，完整日期才写主发行日期。选择封面时替换旧专辑封面选用，选择曲目表时才同步实际曲目与顺序。名称修改不改变原名，合并不修改用户已保存的关联页面。详情的来源编号与页面记录最近一次合并平台，保留下来的人工或旧字段不会因此被覆盖，也不表示这些字段全部来自最近平台。专辑修订保护关联变更后的旧比较，保存回执支持候选失效后的幂等重放。

## 每个插件的代理设置

在「插件管理」中点击对应刮削插件的「配置」，可为当前账号的这个插件选择网络方式。默认「跟随服务端环境」使用 Server 进程的 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NO_PROXY`，不会自动读取浏览器、Windows 系统代理或 PAC；「直连」忽略环境代理；「自定义代理」要求填写代理地址。

自定义地址支持 `http://`、`https://`、`socks5://` 和 `socks5h://`，例如 `http://127.0.0.1:7890`。地址以 Server 所在主机为准；部署在容器中的 `127.0.0.1` 指向容器本身。当前自定义地址不支持用户名和密码，也不接受路径、查询参数或片段。需要认证的服务端环境代理仍由 Go 的环境代理机制处理，其凭据不会进入配置页或插件管理快照。

设置按账号和插件独立保存，重启后保留，保存后新请求立即生效；正在进行的请求继续使用开始时的设置。搜索、同一插件内部的跨站查询、Server 的曲目封面下载及允许的图片重定向使用同一代理配置；Cover Art Archive 内部的 MusicBrainz 查询也遵循 Cover Art Archive 的设置。作品／专辑页面直接展示的远程图片由浏览器访问，不经过服务端代理。图片主机与重定向白名单仍生效。

在线插件通过 `sdk/scraper.SettingsProvider` 自行声明 `scraper-proxy-v1` 设置页，字段为 `proxyMode`（`environment`、`direct`、`custom`，默认 `environment`）和 `proxyUrl`（默认空字符串）。宿主复用 `GET/PUT /api/v1/plugin-settings/{pluginId}` 及现有每用户持久表，保存前执行插件校验；非法地址不会覆盖已保存值。设置保存使用乐观修订，过期请求返回 `CONFLICT`；响应不确定时重新读取确认，不提供设置写入的成功幂等重放。

## 插件与 HTTP 契约

插件实现 `sdk/scraper.Plugin`，提供 `Descriptor` 和 `Search`。声明包括 `type=scraper`、稳定的插件编号、支持的 `fields` 和配置状态。图片来源通过 `imageHosts` 显式声明。插件管理按 `scraper` 用途列出，内置能力直接取插件声明。

- `GET /api/v1/scrapers` 列出在线插件及其字段。本地提取实例按原有 `GET /api/v1/scraper-instances` 查询。
- `POST /api/v1/scrapers/{id}/search` 接受一个字段和结构化查询，查询结果包括来源信息及短期候选令牌。Server 在内存中缓存 `albumDetails` 和 `albumTracks` 的查询结果，按用户、插件、设置修订和查询条件区分。缓存最多保留 24 小时，在容量不足或服务重启后重新读取。客户端可在请求顶层传入 `"refresh": true` 主动访问上游。刷新失败时返回错误并保留此前成功的结果。命中缓存的搜索也会签发新的选用令牌。
- `PUT /api/v1/works/{id}/scraped-fields/{field}` 人工选用作品的一个字段。请求提供 `pluginId`、`candidateToken`、`expectedRevision` 和幂等键。用 `GET /api/v1/works/{id}/scraped-fields` 读取已保存的资料。
- `GET /api/v1/library/albums/{id}/scraped-fields` 读取当前用户音乐专辑已选用的资料；`PUT /api/v1/library/albums/{id}/scraped-fields/{field}` 按音乐专辑修订选用 `albumDetails`、`albumTracks` 或 `artwork`，请求提供 `pluginId`、`candidateToken`、`expectedRevision` 和幂等键，成功返回新的 `revision`。重放相同成功请求不依赖短期候选仍然有效。
- `PUT /api/v1/library/albums/{id}/scraped-fields` 原子选用详情和全部曲目，请求为 `{expectedRevision,pluginId,candidates:{albumDetails,albumTracks,artwork?}}`，候选值均为短期令牌；要求同插件、同发行版，且曲目表非空。成功后统一递增专辑与曲库修订并返回 `{revision}`。单字段接口仍可独立选封面。
- `PUT /api/v1/library/albums/{id}/metadata-merge` 请求为 `{expectedRevision,pluginId,candidates:{albumDetails,albumTracks},fields:[...]}`，完整两候选仍须同插件及发行版；`fields` 为非空去重白名单：`name`、`artist`、`releaseDate`、`publisher`、`genre`、`description`、`cover`、`tracks`。选中的可空值缺失时清空该字段；名称不能为空。预览和合并分别进行，保存成功返回新的 `{revision}`。
- `PUT /api/v1/source-tracks/{id}/scraped-fields/{field}` 支持 `lyrics` 和 `artwork`。请求还需提供 `assetId` 与 `assetVersion`；修订从该来源曲目的媒体选择接口读取。成功后通过现有媒体接口读取正文与来源。
